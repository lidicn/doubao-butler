# 调研笔记：OpenOctopus — Realm 分域 + Summon 实体 Agent

> 调研日期：2026-09-09
> 目的：学习多 Agent 家庭系统的分域治理、角色适配、实体 Agent 化
> 项目：[OpenOctopus](https://github.com/open-octopus/openoctopus)
> 技术栈：Node.js 22+ / TypeScript / SQLite / pgvector

---

## 一、项目定位

**"AI family home hub. One event, every member, the right context. Summon anything into a living agent."**

不是又一个统一聊天框，而是**家庭群聊中的一个家庭成员**。把家庭生活分成多个 Realm（域），每个域有独立的知识库、Agent 团队、技能集。像章鱼一样，每条触手有自己的神经中枢自主行动，中央大脑协调一切。

---

## 二、核心概念

### 2.1 Realm（域）

家庭生活的独立分区，每个域有：
- 独立的知识库
- 独立的 Agent 团队
- 独立的技能集
- 独立的记忆

**内置 12 个域模板**：

| 域 | 内容 | 示例 Agent |
|---|---|---|
| pet | 宠物、兽医、食物记录 | 健康顾问、Momo（召唤的宠物） |
| parents | 父母、健康档案 | 照护助手、Mom（召唤的母亲） |
| partner | 伴侣、纪念日 | 关系顾问 |
| finance | 账户、投资、债务 | 预算规划师、税务助手 |
| work | 项目、同事、目标 | 任务管理、周报员 |
| legal | 合同、案例、法条 | 合同律师、劳动法顾问 |
| vehicle | 车、保险、保养 | 保养追踪、成本报告 |
| home | 房屋、家电、维修 | 家庭管家 |
| health | 体检、处方 | 健康监控 |
| fitness | 训练计划、身体数据 | 健身教练 |
| hobby | 项目、学习材料 | 学习教练 |
| friends | 社交圈、活动 | 社交雷达 |

域可以自由创建、合并、删除。以上是起始模板。

### 2.2 Summon（召唤）

**杀手级功能**：把现实世界的实体变成有记忆、有个性、有主动性的 AI Agent。

```
原始数据 → 结构化实体 → SUMMON → 有记忆/个性/主动性的 Agent
```

| 实体类型 | 示例 | 召唤后能做什么 |
|---|---|---|
| **生物** | 宠物、家人、朋友 | 模拟对话、个性、情感表达 |
| **资产** | 车、房子、投资组合 | 状态监控、保养提醒、成本报告 |
| **组织** | 公司、医院 | 流程指南、联系人管理 |
| **抽象** | 目标、项目、习惯 | 进度追踪、偏差提醒、回顾 |

**示例场景**：
```
你："我下周要出差 5 天。"
  ↓
Momo（宠物）："谁来喂我遛我 5 天？！"
Mom（父母）："妈刚说她想来——她可以照顾 Momo。"
Car（车）："出发前充满电？还是打车去机场？"
Budget（财务）："出差预算估算 ¥X。记得留小票。"
  ↓
系统编译"出差准备清单"供你审批
```

实体的个性定义在 **SOUL.md** 文件中（类似 Agent 的 system prompt，但更丰富）。

### 2.3 智能家庭路由（Intelligent Family Routing）

**同一事件，按角色推送不同上下文**：

- 爸爸 → 行动项 + 病史
- 妈妈 → 协调视图
- 爷爷 → 大字体要点
- 孩子 → 简化信息

这是 OpenOctopus 最独特的设计：不是群发给所有人同样的内容，而是根据家庭成员的角色和需求，**个性化推送**。

### 2.4 双层技能（Dual-layer Skills）

| 层级 | 范围 | 示例 |
|---|---|---|
| **全局技能** | 所有域可用 | 搜索、日历、邮件、国际化 |
| **域技能** | 仅当前域可用 | 兽医查询、税务计算、法律搜索 |

### 2.5 Agent Teams（三层 Agent 架构）

```
中央 Agent（全局）
├── Router — 意图检测 & 域路由
├── Coordinator — 跨域分析
└── Scheduler — 主动触发 & 定时任务

域 Agent（每个域内）
├── Professional — 专业 Agent（律师、预算规划师、健康监控）
└── Summoned ✦ — 召唤的实体 Agent（Momo、Mom、我的车）
```

### 2.6 RealmHub（域市场）

像应用商店，但卖的是**完整的域包**：
- "法律顾问团队" — 实体模板（律师/合同/法条）+ 3 个 Agent + 技能
- "宠物护理" — 宠物档案 + 健康顾问 + 兽医查询 + 疫苗追踪
- "家庭财务" — 账户 + 预算规划师 + 投资分析器

每个包包含：域模板、实体模板、Agent 配置、技能配置、示例数据。

### 2.7 Governance（治理）

每个 Agent 行动遵循信任链：
- **人在回路** — 关键行动需要明确审批
- **审计日志** — 每个 Agent 决策的完整追踪（证据/结果）
- **隐私层级** — 按域权限控制，域间数据隔离
- **预算限制** — 每个 Agent/域/行动的 token 和成本上限

## 五、对豆包管家的启示

### 5.1 直接可抄的 3 个点

#### ① Realm 分域治理（优先级：P1，v1.6-v1.7）

**当前豆包管家的状态**：所有知识/技能/Agent 混在一起，没有域的概念。

**抄法**：
- 把家庭生活分成几个域：**设备域**（HA/TV/电脑）、**日程域**（课程表/日历/提醒）、**家庭域**（成员/留言/防沉迷）、**运维域**（new-api/docker/NAS）
- 每个域有独立的知识库、技能集、Agent 配置
- 域间通过知识图谱链接（比如设备域的"客厅电视"链接家庭域的"Kevin 防沉迷"）
- Router Agent 根据用户意图自动路由到对应域

**跟豆包管家现有系统的对齐**：
- 技能系统已经支持分类，可以按域组织技能
- 角色系统可以映射到域（小爱=设备域、小甜菜=家庭域、豆包管家=全局路由）
- 决策层可以作为跨域 Coordinator

#### ② 智能家庭路由 — 按角色推送不同上下文（优先级：P1）

**当前豆包管家的状态**：Bark/TTS 推送是统一内容，所有人收到一样的。

**抄法**：
- 同一事件，根据接收者角色生成不同版本的内容
- 示例："Kevin 在客厅玩 Xbox 超过 2 小时"
  - 推给 lidicn → "Kevin 已玩 Xbox 2 小时，超过工作日限制。是否强制结束？[A 结束] [B 再玩 30 分钟] [C 忽略]"
  - 推给 Kevin（手表/小甜菜）→ "你已经玩了 2 小时啦，今天的时间快用完了，要不要休息一下眼睛？"
  - TTS 到客厅音箱 → 温和提醒（不暴露监控感）
- 在推送层加一个"角色适配"中间件，根据 target_role 生成不同话术

#### ③ Summon — 实体 Agent 化（优先级：P2，v1.7+）

**当前豆包管家的状态**：角色系统有 8 个角色，但都是"功能角色"（管家/小爱/小甜菜等），没有"实体角色"。

**抄法**：
- 把家庭成员（lidicn/Kevin/Emily）的设备/数据/习惯"召唤"成 Agent 画像
- 不是让他们变成对话 Agent，而是让管家**理解每个成员的状态和偏好**
- 示例：
  - "Kevin 画像" → 知道他的课程表、Xbox 使用习惯、手表位置、喜欢的提醒方式
  - 管家在做决策时，可以引用这些画像（"Kevin 今天有数学课，现在玩 Xbox 可能影响作业"）
- 用 **SOUL.md** 风格的文件定义每个成员的画像（个性/偏好/习惯/设备），跟现有的角色配置对齐

### 5.2 值得参考但不急的 2 个点

#### ④ RealmHub 域市场

豆包管家当前是个人项目，不需要市场。但可以借鉴"域包"的概念：把一个完整的域（含技能/Agent/知识库/示例数据）打包成可导入的配置包，方便备份和迁移。

#### ⑤ Governance 治理（预算限制）

OpenOctopus 的"每个 Agent/域/行动的 token 和成本上限"值得参考。豆包管家可以在角色/技能层面加 token 预算限制，防止某个角色或技能消耗过多。这个可以跟 v1.4 的自进化（低质量技能重写）一起做。

### 5.3 豆包管家已经做得更好的地方

| 能力 | OpenOctopus | 豆包管家 |
|---|---|---|
| 设备控制 | 无（纯生活管理） | HA+TV+电脑三端控制 |
| 多端辐射 | Web+CLI | 电脑+电视+手机 PWA |
| 定位引擎 | 无 | 多源融合定位（v1.5） |
| 语音/TTS | 无 | EdgeTTS+小爱音箱+多角色音色 |
| 主动决策 | Scheduler（简单定时） | 决策层+触发器+模式引擎 |
| 技能生态 | 简单双层技能 | 版本+沙箱+模板+自进化+隔离 |
| 物理空间感知 | 无 | ArcFace+人在传感器+设备追踪 |

## 六、落地建议

### 近期（v1.6）

1. **Realm 分域**：先分 3 个域——设备域、日程域、家庭域。每个域有独立技能集和知识库。Router 根据意图路由。
2. **角色适配推送**：在 Bark/TTS 推送层加角色适配中间件，同一事件不同角色收到不同内容。

### 中期（v1.7）

3. **Summon 成员画像**：为 lidicn/Kevin/Emily 建立 SOUL.md 风格的画像文件，管家决策时引用。
4. **跨域知识图谱**：链接设备域和家庭域（如"客厅电视"↔"Kevin 防沉迷"）。

### 不做

- 不做 12 个域（先 3 个，够用再加）
- 不做 RealmHub 市场（个人项目不需要）
- 不做 Node.js 重写（Python 够用）
- 不做召唤实体对话 Agent（先做画像，不做对话）
