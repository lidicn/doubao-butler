## 二、为什么 X08A 必须走云端停止？

### 2.1 本地停止全部无效

| 方案 | 结果 | 原因 |
|---|---|---|
| HA `media_player.media_stop` | 无效 | X08A 固件忽略本地 stop 指令，虽然 supported_features 显示支持 |
| HA `media_player.media_pause`（单次） | 无效 | X08A 固件自动恢复播放（把 TTS 当成电台流） |
| HA `media_player.media_pause`（连续 5 次） | 有效 | 能阻止自动恢复，但会截断音频 |
| `player_set_loop 0` | 无效 | X08A 固件级单曲循环，API 无法关闭 |
| `intelligent_speaker` 发"嗯"打断 | 无效 | 只是打断语音交互，不影响音乐播放 |

### 2.2 结论

**X08A 触屏音箱 Pro 8 必须走云端 `player_play_operation stop` 才能可靠停止！**

本地方案要么无效，要么截断音频，要么需要复杂的轮询逻辑。云端方案是前任开发者反复验证后的最优解。

## 三、Token 从哪里来？

### 3.1 错误的来源（已废弃）

❌ **从 HA 的 `core.config_entries` 读取**：
- 这是小米 IoT 平台的 token（sid=`xiaomiio`）
- 不能用来调用小爱音箱 API（sid=`mico`）
- 调用会返回 401 Unauthorized

### 3.2 正确的来源（当前使用）

✅ **从 Songloft 的 accounts 文件读取**：

```
路径：/vol1/1000/docker/songloft-player/data/jsplugins_data/miot/data/accounts
```

**文件格式**：
```json
"[{\"id\":\"23802665\",\"services\":{\"micoapi\":{\"service_token\":\"...\",\"ssecurity\":\"...\",\"expires_at\":...}},\"devices\":[...] }]"
```

**注意**：文件内容是**字符串形式的 JSON 数组**，需要解析两层：
```python
raw = open(path).read()
accounts = json.loads(json.loads(raw))  # 解析两层
service_token = accounts[0]["services"]["micoapi"]["service_token"]
user_id = accounts[0]["user_id"]
```

### 3.3 Token 自动刷新

管家每小时自动从 Songloft accounts 文件读取最新 token，完全不需要手动更新。

**为什么用 Songloft 的 token？**
- Songloft 是开源音乐服务器，已经实现了完整的小米账号扫码登录和 token 自动刷新
- 管家直接复用 Songloft 的 token，不需要自己实现小米 OAuth 鉴权
- Songloft 自己会处理 token 过期和刷新，管家只需要读文件即可

## 四、TTS 播放流程

### 4.1 播放语音

```
POST https://api2.mina.mi.com/remote/ubus
  deviceId: <xiaoai_id (UUID)>
  method: player_play_music
  message: {"startaudioid": "...", "music": "..."}
```

**注意**：X08A 必须用 `player_play_music`（标准音乐 payload），不能用 `player_play_url`（X08A 不拉音频）。

### 4.2 停止播放

```
POST https://api2.mina.mi.com/remote/ubus
  deviceId: <xiaoai_id (UUID)>
  method: player_play_operation
  message: {"action": "stop", "media": "app_ios"}
```

**云端延迟**：~700ms（实测 600-800ms）

### 4.3 精确停止时机

**当前方案**：提前量 400ms（实测最优）

```python
while playing:
    pos, dur, status = get_play_status(device_id)
    if status == 1 and pos >= duration - 400:
        stop_playback(device_id)  # 400ms 后到达设备时刚好播完
    if position 突降（回环）:
        stop_playback(device_id)  # 兜底
    sleep(0.1)
```

**提前量调优记录**：
- 800ms：截断（停止太早，音频没播完就停了）
- 400ms：完美（刚好播完，不截断，不循环）

## 七、踩坑记录

### 7.1 为什么不能直接用 HA 的 token？

HA 的 xiaomi_miot 集成用的是 **小米 IoT 平台**（sid=`xiaomiio`）的 token，用于控制智能设备（灯、空调等）。

小爱音箱 API 用的是 **小爱音箱平台**（sid=`mico`）的 token，用于控制音箱播放。

这两个平台的 token **不通用**，即使是同一个小米账号。

### 7.2 为什么不能用本地 media_pause？

X08A 固件把远程音频 URL 当成"网络电台流"处理，会：
1. 单曲循环播放
2. 忽略本地 stop 指令
3. 暂停后自动恢复播放

只有云端 `player_play_operation stop` 才能真正停止。

### 7.3 为什么提前量是 400ms？

- 云端延迟约 600-800ms
- 提前量 = 云端延迟 - 100ms（余量）
- 所以提前量 400ms 时，停止指令到达设备时刚好播完（剩下 100ms 的句尾静音，人耳无感）
