# AF 主动询问 MQTT 语音腿 · DB 侧交接回执（2026-11-08）

对应来件：AF-PM《MQTT 主动询问（ask）语音腿 · 开发与联调准备提示词》（2026-11-08）。
线协议以 AF `af_mqtt_bridge.py` v1.28.3 为准，本回执只说明 DB 侧怎么实现、怎么验。

## 一、已实现

| 环节 | 实现 |
|---|---|
| 订阅提问 | `af/ask/pending`，QoS1，**retain=false**（⛔ retained：重连会重复问） |
| 载荷校验 | `{ask_id ≤64 字符, room(HA area_id), prompt, source, priority, timeout_remaining}`；坏件丢弃＋`ADM_ERR_PAYLOAD_INVALID` 留痕 |
| 念题 | `dialog.speak_as_role(role=butler, prompt, room, member="系统")`：按房间选箱、回声抑制、无设备出声记 `AF_ASK_UNSENT` |
| 收回答 | `xiaomi_ear` 转写回调 `AfAskManager.on_transcript`（**在唤醒词匹配之前**截获，回答不必带唤醒词） |
| 分类 | 先否后是；`要/好/是/开/行/可以/需要/嗯/对/ok/yes` → yes；`不要/不用/不需要/不行/不是/不/否/别/关/no` → no；带参数（数字/度/℃/百分）**整条拒收**；听不清/静默**不发** |
| 发回 | `af/ask/answer`：`{ask_id, answer: "yes"|"no", raw_text}`，QoS1，retain=false |
| 去重/串行/超时 | 同 `ask_id` 只念一遍（1h 窗）；同房间串行；超过 `timeout_remaining` 的晚到回答丢弃 |
| 日志码 | `AF_ASK_SPOKEN` / `AF_ASK_LISTENING` / `AF_ASK_ANSWER_SENT` / `AF_ASK_REJECTED` / `AF_ASK_TIMEOUT` / `AF_ASK_UNSENT` / `AF_ASK_DEDUPED` / `AF_ASK_LATE_DROP` |

代码：`butler/bus/af_ask.py`；装配：`butler/app.py`（`_consume` 懒建 `AfAskManager`，关停腿 `close()`）；主题常量：`butler/bus/topics.py`。
测试：`tests/test_af_ask_mqtt_voice_leg.py`（20 例，含分类/去重/过期/参数拒收/晚到/跨房/同房串行/装配形状）。

## 二、DB 侧不需要任何新配置

订阅与发布会随现有 MQTT 客户端（同一 broker）自动生效，无开关、无新增 `.env` 键。

## 三、联调时 DB 侧怎么验

1. 重启后日志出现 `af_ask voice leg initialized`；MQTT `connected` 后订阅表含 `af/ask/pending`（`butler.bus.topics.SUB_TOPICS`）。
2. AF 发一条 pending 后：日志 `AF_ASK_SPOKEN`（含 room/设备）→ 用户答「要」→ `AF_ASK_ANSWER_SENT answer=yes`。
3. 用户不答：`AF_ASK_TIMEOUT`（不发答案）；答「开到 24 度」：`AF_ASK_REJECTED 原因=param`（不发答案）。

## 四、边界（与来件一致）

- ⛔ DB 侧不改 AutoForge 任何代码/配置/主题命名。
- ⛔ 不做多值/带参数回答解析；⛔ 不做跨房间并发（同房间串行）。
- 疑问经出资人转 AF-PM。
