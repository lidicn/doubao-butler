## 二、M1-M2：多模态截图分析工具（详细）

### 工具定义
```
工具名：analyze_screenshot
参数：
  - target (str, required): "desktop"（桌面）或 "tv"（电视）
  - prompt (str, optional): 分析问题，默认"请详细描述当前屏幕内容，包括打开的窗口/应用/文字/状态"
  - detail (str, optional): "brief"（简短）或 "detailed"（详细），默认 "brief"
返回：多模态 LLM 对截图的文字描述
```

### 实现逻辑
1. 根据 target 调用对应截图工具：
   - desktop → desk_desktop_screenshot（DeskPilot API）
   - tv → tv_screenshot（TVPilot API）
2. 从截图结果中提取 base64 图片数据
3. 转换为 data URL：`data:image/jpeg;base64,{base64_data}`
4. 调用 `agent.doubao.vision(prompt, image_url=data_url)`
5. 返回分析文本

### 关键代码
```python
def _screenshot_to_data_url(screenshot_result: dict) -> str | None:
    """从截图工具返回结果中提取 base64 并转 data URL。"""
    image_b64 = screenshot_result.get("image") or screenshot_result.get("screenshot")
    if not image_b64:
        return None
    # 去掉可能的 data URL 前缀
    if image_b64.startswith("data:"):
        return image_b64
    # 检测格式（默认 jpeg）
    return f"data:image/jpeg;base64,{image_b64}"

async def _analyze_screenshot(agent, args: dict) -> str:
    target = args.get("target", "desktop").lower()
    prompt = args.get("prompt", "请详细描述当前屏幕内容，包括打开的窗口/应用/文字/状态")
    detail = args.get("detail", "brief")

    if detail == "brief":
        prompt += "。请用简短的语言回答，不超过100字。"

    # 1. 截图
    if target == "desktop":
        screenshot = await _dispatch_deskpilot(agent, "desktop_screenshot", {})
    elif target == "tv":
        screenshot = await _dispatch_tvpilot(agent, "screenshot", {})
    else:
        return f"❌ 不支持的 target: {target}，请使用 desktop 或 tv"

    # 2. 转 data URL
    data_url = _screenshot_to_data_url(screenshot)
    if not data_url:
        return f"❌ 截图失败或无法提取图片数据: {str(screenshot)[:200]}"

    # 3. 多模态分析
    try:
        text, _ = await agent.doubao.vision(prompt, data_url)
        return f"📸 {target} 截图分析：\n{text}"
    except Exception as e:
        return f"❌ 多模态分析失败：{e}"
```

## 三、M3：ReAct 观察策略集成

### 当前策略
- ReAct 观察主要靠结构化数据（窗口标题/当前状态/工具返回值）
- 截图只在工具调用时获取，不做 LLM 分析

### v1.3 优化
- 在 ReAct 循环中，当结构化数据不足以判断当前状态时，自动调用 analyze_screenshot
- 触发条件：
  1. 连续 2 步结构化观察无变化
  2. 工具返回结果模糊（如"操作完成"但不确定实际效果）
  3. 用户明确要求"看看现在什么情况"
- 观察结果写入 ReAct 轨迹，可用于技能沉淀

## 四、M5-M7：技能市场

### 技能导出
- `GET /api/skills/{skill_id}/export` → 返回技能 JSON 文件
- 包含完整技能定义（触发/大脑/步骤/参数/版本）

### 技能导入
- `POST /api/skills/import` → 上传 JSON，校验格式，保存为新技能
- 校验：必填字段/工具存在性/参数完整性
- 冲突处理：同 ID 技能自动加版本号

### 版本管理
- 技能文件增加 version 字段（默认 1）
- 修改技能时自动递增版本，旧版本存入 _versions/ 目录
- `GET /api/skills/{skill_id}/versions` → 版本列表
- `POST /api/skills/{skill_id}/rollback` → 回滚到指定版本

## 五、M8-M9：技能自动优化

### 质量统计扩展
- 技能执行记录表增加：success（bool）、step_count、duration_ms、error_type
- `GET /api/skills/stats` → 每个技能的执行次数/成功率/平均步数/平均耗时

### 低质量技能发现
- 规则：
  1. 成功率 < 50%（执行 ≥3 次）
  2. 平均步数 > 10（简单任务）
  3. 平均耗时 > 60s
  4. 最近 7 天失败率上升

### LLM 重写建议
- 对低质量技能，调用 LLM 分析失败轨迹，生成优化建议
- `POST /api/skills/{skill_id}/optimize` → 返回重写建议+优化后技能草稿
- 用户确认后替换原技能

## 七、风险与阻塞

| 风险 | 影响 | 缓解 |
|------|------|------|
| 多模态 token 消耗大 | 额度紧张 | 默认 brief 模式+缓存+截图压缩（DP v2.8） |
| doubao vision 接口不稳定 | 分析失败 | 降级到结构化观察，不阻塞 ReAct |
| 技能导入格式不统一 | 导入失败 | 严格校验+错误提示+模板下载 |
| new-api 额度 | 所有 LLM 调用 | 精简 prompt，非必要不调用多模态 |
