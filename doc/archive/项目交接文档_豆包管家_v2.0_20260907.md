## 一、项目概述

豆包管家（doubao-butler）是家庭 AI 管家系统，作为家庭 AI 生态的**中枢**，对接：

- **耳朵**：小爱音箱（全屋6个房间）、电视遥控器语音键
- **眼睛**：memory-agent（人脸识别、视觉多模态、家庭摄像头）
- **大脑**：new-api（butler-chat 专属模型，agnes-2.5-flash）
- **嘴巴**：edge-tts / 小爱 TTS / TV 端通知
- **手机端**：doubao2api（豆包 app 对话同步，6个角色各一个对话）
- **设备控制**：Home Assistant（HA API）
- **电视控制**：TV端（IPTV换台、飞牛TV点播）
- **编排**：内置触发器引擎（已从 Node-RED 迁移到容器内）

### 核心定位

家庭 AI 生态中枢，所有 LLM 调用、记忆存储、角色管理、技能编排统一在 butler 完成。其他项目（memory-agent、autoflow、DeskPilot、TV_CAM、zap_tv）作为感知层或执行层，需要 LLM 时通过 butler 中枢调用。

## 十、部署与开发规范

### 10.1 部署方式

```bash
# 1. 修改本地文件
# 2. scp 到 NAS
scp local_file.py lidicn@192.168.2.200:/tmp/

# 3. docker cp 到容器
docker cp /tmp/file.py doubao-butler:/app/butler/file.py

# 4. 执行 patch 脚本（如果需要）
docker exec doubao-butler python3 /tmp/patch.py

# 5. 重启容器
docker restart doubao-butler

# 6. 验证
docker logs doubao-butler --since 30s
curl -s -H 'Authorization: Bearer <redacted>' http://localhost:8095/api/...
```

### 10.2 重要注意事项

1. **容器重建后 docker cp 修改会丢失**：需要重新 cp 或 rebuild docker image
2. **PowerShell 内联 python 代码会被解析错误**：必须用脚本文件方式（scp 到 /tmp/ 再 docker exec python3 执行）
3. **compose 中已配置 MEMORY_AGENT_BUTLER_TOKEN**：重建容器时必须基于含该环境变量的 compose
4. **webui 静态文件**：在 `butler/static/` 目录，修改后需重启容器生效
5. **数据持久化**：`/app/data/` 目录挂载到 NAS，重启不丢失

| 问题 | 结论 |
