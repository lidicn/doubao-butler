# 豆包管家 v1.6 自进化版本路线图

> 版本：v1.6 | 日期：2026-09-12
> 主题：全链路自进化——从多个数据源学习，自动沉淀优化
> 前置：v1.5 Koin 轻 Agent（已完成）

---

## 一、当前架构回顾

```
入口层：手机APP / PWA / WebUI管家 / DeskPilot / TVPilot / 小爱音箱(miio)
  ↓
Koin 轻 Agent 引擎
  ├─ 第一层：快速路由（关键词匹配，0 LLM）
  │   ├─ 天气 / 时间 / 谁在家
  │   └─ 未来：自动沉淀的规则
  ├─ 第二层：LLM Function Calling
  │   └─ 模糊意图 → 调工具
  └─ 第三层：自进化轨迹记录
      └─ agent_traces 表
```

## 二、自进化六大方向

### M1：Koin 快速路由自动沉淀

**问题**：现在快速路由规则是手写的，高频LLM路径没有自动转成快速规则。

**方案**：
1. 定期扫描 `agent_traces` 表，筛选 `llm_calls>0` 且 `status=ok` 的记录
2. 同一个意图模式出现≥3次 → 提取关键词
3. 生成候选快速路由规则
4. WebUI 展示候选规则，用户一键确认后加入快速路由表

**数据源**：agent_traces 表（已有）

**预期效果**：快速命中率从当前水平逐步提升，省 token、降延迟。

---

### M2：设备别名学习

**问题**：用户说"客厅那个灯""书房的空调"，DEVICE_MAP 里没有别名，LLM 每次都要猜。

**方案**：
1. 记录每次设备控制成功时的用户原话
2. LLM 分析：用户说的词 → 实际操作的 entity_id
3. 自动学习别名映射："客厅那个灯" → `light.philips_cn_xxx`
4. 存入别名表，下次快速路由直接命中

**数据源**：
- 手机APP对话记录（已有）
- 小爱音箱语音记录（待接入数据库，见 M6）
- WebUI 管家对话（已有）

---

### M3：失败模式学习

**问题**：设备控制经常失败，比如"温度调到26度"格式不对，但每次都重新犯。

**方案**：
1. 记录所有设备控制失败（webhook 标签解析失败 / LLM调工具失败）
2. 分析失败模式：哪些操作经常失败？什么原因？
3. 自动修正：如果"设定温度 26℃"格式总是失败，自动改成正确格式
4. 生成提示词更新建议，用户确认后更新设备说明书

**数据源**：
- 手机APP webhook 失败记录（已有）
- agent_traces 里 tool_calls 失败记录（已有）
- Bark 失败推送记录（已有）

---

### M4：场景自动推断

**问题**：用户手动配置场景（观影/睡眠/晨起）很麻烦，其实从使用模式能自动推断。

**方案**：
1. 分析 HA 事件 + 时间模式
2. 比如：每晚 19:00 → 开客厅灯+开电视
3. 自动推断为"晚间场景"候选
4. WebUI 展示推断结果，用户确认后生成正式场景

**数据源**：
- HA 设备事件（通过 MA 或直接订阅）
- 时间模式分析

---

### M5：记忆自动整理

**问题**：记忆提取已经做了，但提取出的事实需要人工审核投喂，流程长。

**方案**：
1. 记忆提取器自动从对话中提取事实
2. LLM 自动分类：明确事实（直接投喂）/ 模糊事实（待审核）/ 错误事实（忽略）
3. 明确事实自动加入长期记忆候选池
4. WebUI 一键批量审核确认

**数据源**：对话存储（已有）+ 记忆提取器（已有）

---

### M6：小爱音箱数据接入

**问题**：小爱音箱已通过 miio 完全接入管家，语音操控设备的数据没进数据库。

**方案**：
1. 小爱语音指令 → 管家 webhook → 执行设备控制
2. 记录每次语音指令的原话 + 执行结果到 agent_traces
3. 这样 Koin 轨迹里就有小爱语音的数据了
4. 支撑 M1（快速路由沉淀）和 M2（设备别名学习）

**数据源**：小爱 miio 对话记录（待落库）

## 三、技能自进化（完善现有）

当前技能自进化只能监控告警，不能生成新技能。完善方向：

| 现有能力 | 不足 | v1.6 改进 |
|---|---|---|
| 分析技能失败率 | 只告警 | 自动生成修复建议草稿 |
| LLM重写建议 | 只出文字 | 生成完整新技能JSON，一键部署 |
| 未使用技能检测 | 只建议禁用 | 自动归档到草稿区，不直接删 |

**新增**：从 M1（Koin快速路由沉淀）积累的规则，自动转换为技能定义（skills/ 下的 JSON 文件）。

## 六、风险控制

1. **自动沉淀需人工确认**：所有自动生成的规则/技能都先入候选池，用户确认后才生效
2. **快速路由误命中**：快速路由失败时自动降级走 LLM，不影响体验
3. **别名冲突**：一个别名对应多个设备时，走 LLM 歧义消解
4. **数据隐私**：所有自进化数据只存本地 NAS，不上云
