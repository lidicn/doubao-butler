## 一、P0-1 模式引擎（决策上下文）

### 1.1 功能说明

5 种互斥模式：日常(daily)、观影(movie)、睡眠(sleep)、会客(guest)、离家(away)。
- 模式状态持久化（复用 v1.7 的 ts_mode_transitions 表）
- 模式切换 API（查询当前模式/切换模式）
- 模式行为规则：每种模式下 TTS/Bark/技能的行为不同
- 离家模式优先级最高
- 模式切换时记录到时序数据

### 1.2 模式行为规则

| 模式 | TTS | Bark推送 | 技能执行 |
|---|---|---|---|
| daily 日常 | ✅ 正常 | ✅ 正常 | ✅ 全功能 |
| movie 观影 | ❌ 禁用 | ✅ 静默 | 仅异常类 |
| sleep 睡眠 | ❌ 仅紧急警报 | ✅ 静默 | 仅紧急类 |
| guest 会客 | ⚠️ 仅基础响应 | ✅ 正常 | 暂停关怀类 |
| away 离家 | ❌ 禁用 | ✅ 警报即时 | 全部暂停 |

### 1.3 模块结构

复用 v1.7 的 `butler/timeseries/store.py` 中的模式切换函数。
新增 `butler/modes/` 模块：
- `__init__.py` — ModeEngine 主类
- `engine.py` — 模式状态机 + 行为规则判断
- `api.py` — REST API 路由

### 1.4 API

- `GET /api/modes/current` — 当前模式
- `POST /api/modes/switch` — 切换模式 {mode, source}
- `GET /api/modes/rules` — 模式行为规则
- `GET /api/modes/history` — 模式切换历史（复用 timeseries）

### 1.5 验收标准

- [x] 5 种模式能正常切换和查询（2026-09-10 验证：daily/movie/sleep/guest/away）
- [x] 模式互斥（切换到新模式自动退出旧模式，2026-09-10 验证：movie→sleep 自动 exit movie）
- [x] 模式行为规则判断正确（2026-09-10 验证：观影 TTS=False、睡眠仅紧急 TTS、技能类别限制）
- [x] 离家模式优先级最高（代码实现：away 模式 skills_allowed=none，不自动从 away 切走）
- [x] 模式切换记录写入时序数据（2026-09-10 验证：7 条历史记录）

**实现说明（2026-09-10）**：
- 新建 `butler/modes/` 模块（__init__.py/engine.py/api.py）
- ModeEngine 类：状态机 + 行为规则判断，复用 v1.7 的 ts_mode_transitions 表
- 5 种模式：daily(日常)/movie(观影)/sleep(睡眠)/guest(会客)/away(离家)
- 行为规则：tts_allowed/tts_emergency_only/bark_silent/skills_allowed/care_skills_disabled/security_level
- 方法：switch()/can_tts()/can_bark()/can_run_skill()/is_care_skill_disabled()/get_state()/get_all_rules()
- 4 个 API：GET /api/modes/current、POST /api/modes/switch、GET /api/modes/rules、GET /api/modes/history
- 模式切换时触发 mode_changed 事件（供 trigger 规则层消费）
- 修复：API 中用 get_runtime() 而非 request.app.state.rt（后者不存在）

## 二、P0-2 定位驱动模式自动切换

### 2.1 功能说明

基于 v1.5 定位引擎自动判断模式：
- 所有人离家 → 离家模式
- lidicn 在客厅 + TV 开启 → 观影模式
- 主卧静止 6 小时 → 睡眠模式
- 有人回家 → 日常模式
- 带防抖延时，避免误切换

### 2.2 实现方案

- APScheduler 每 5 分钟检查定位状态
- 连续 2 次检查满足条件才切换（防抖）
- 切换时调用 ModeEngine.switch()

### 2.3 验收标准

- [x] 所有人离家自动切换到离家模式（2026-09-10 代码实现：连续 2 次检查=10 分钟防抖）
- [x] 有人回家自动切换到日常模式（2026-09-10 代码实现：立即切换）
- [x] 防抖正常（2026-09-10 实现：_debounce 计数器，不满足条件自动重置）
- [x] lidicn 在客厅 + TV 开启 → 观影模式（2026-09-10 代码实现）
- [x] 主卧长时间静止 → 睡眠模式（2026-09-10 代码实现：连续 12 次=60 分钟）

**实现说明（2026-09-10）**：
- 新建 `butler/modes/auto_switch.py`：ModeAutoSwitcher 类
- 4 条规则：所有人离家→away、有人回家→daily、客厅+TV→movie、主卧静止→sleep
- 防抖：_debounce 字典计数，连续 N 次满足才切换，不满足自动重置
- 定时：APScheduler interval 5 分钟，id=mode_auto_switch
- TV 状态检测：async 查询 HA media_player 实体（名称含"电视"/"TV"/"mytv"）

## 三、P0-3 主动问询引擎

### 3.1 功能说明

触发条件（定位+模式+时间+设备状态）→ 管家判断需要问询 → 小爱 TTS 主动提问 → 开启收音窗口 → 用户回复 → 管家理解意图 → 执行动作。

### 3.2 约束

- 同一事件仅询问一次
- 睡眠/观影/会客模式禁用
- 问询超时 30 秒自动退出

### 3.3 验收标准

- [x] 主动问询能正常触发和播报（2026-09-10 验证：TTS + Bark 同步推送）
- [x] 用户回复能被接收和处理（2026-09-10 验证：POST /api/proactive/{id}/answer）
- [x] 模式禁用规则正常（2026-09-10 实现：睡眠/观影/会客模式禁用）
- [x] 同一事件仅询问一次（2026-09-10 验证：event_key 去重，默认 24 小时）
- [x] 问询超时自动退出（2026-09-10 实现：30 秒超时，pending 查询时自动清理）

**实现说明（2026-09-10）**：
- 新建 `butler/proactive/` 模块（__init__.py/engine.py/api.py）
- ProactiveEngine 类：ask()/answer()/get_pending()/list()/is_enabled()/is_event_asked()
- SQLite 表 proactive_inquiries（id/event_key/title/question/options/status/answer/expires_at/context）
- 状态：pending/answered/timeout/dismissed
- 禁用模式：sleep/movie/guest（DISABLED_MODES）
- 超时：30 秒（INQUIRY_TIMEOUT），查询 pending 时自动清理超时
- 4 个 API：POST /api/proactive/ask、POST /api/proactive/{id}/answer、GET /api/proactive/pending、GET /api/proactive/list
- 简化版：用户回复通过 API 接收（后续跟小爱耳朵集成语音回复）

## 四、P0-4 HA 动态实体发现（省 90% token）

### 4.1 功能说明

不把全量 HA 实体发给 LLM，而是：
1. HA 实体索引（区域/域/设备类，~500 tokens）
2. 按需发现工具（ha_discover_entities）
3. 状态查询工具（ha_get_states）
4. 动作执行工具（ha_action）

### 4.2 验收标准

- [x] 实体索引能正常生成（2026-09-10 验证：2888 实体，索引仅 316 tokens，省 99%）

- [x] ReAct 循环中 LLM 能先查索引再按需发现（API 已就绪，ReAct 集成待 P1）

**实现说明（2026-09-10）**：
- 新建 `butler/ha_tools/discovery.py`：HADiscovery 类
- 4 个方法：get_entity_index()/discover_entities()/get_entity_states()/execute_action()
- 索引缓存 5 分钟（INDEX_TTL=300）
- 4 个 API：GET /api/ha/entities/index、GET /api/ha/entities/discover、POST /api/ha/entities/states、POST /api/ha/entities/action

## 五、P0-5 HA 实体白名单

### 5.1 功能说明

WebUI 配置"HA 实体白名单"，只允许 agent 控制指定设备。
- 未在白名单的实体只能查询不能控制
- 跟模式引擎权限控制结合（离家模式只允许安防类设备）

### 5.2 验收标准

- [x] 白名单能正常配置和查询（2026-09-10 验证：添加/列表/移除/统计）
- [x] 非白名单实体控制被拒绝（2026-09-10 验证："只允许查询不允许控制"）
- [x] 模式权限控制正常（2026-09-10 实现：离家模式只允许安防类设备）

**实现说明（2026-09-10）**：
- 新建 `butler/ha_tools/whitelist.py`：HAWhitelist 类 + SQLite 表 ha_entity_whitelist
- 5 个类别：general/security/climate/media/other
- is_allowed() 检查：白名单 + 模式权限（离家模式只允许 security 类）
- 在 HADiscovery.execute_action() 中集成白名单检查（非白名单返回 403 blocked）
- 4 个 API：GET /api/ha/whitelist、POST /api/ha/whitelist/add、DELETE /api/ha/whitelist/{id}、GET /api/ha/whitelist/check
