## 1. 项目概览

**一句话**：遥控器语音键 → TV 端小爱 App（Arcface）拦截识别 → 命中"豆包管家"唤醒词 → 打断小爱回复 → 经 MQTT experiment 事件 → doubao-butler（决策大脑）按意图调 `switch_channel` 工具 → MQTT 下发 zap-tv（NAS 轻量容器，设备控制层）→ 自动拉起/保活 mytv 并按频道号数字键换台 → 回执确认 → TTS 播报结果。

**已闭环并验证**：`"豆包管家，换到中央二台"` → 电视切到中央二台 + 语音播报"已经帮您换到中央二台了"（回执带"第6台"）。

**架构原则**（用户定案）：
- **LLM 唯一入口 = butler**，zap-tv 不装 LLM、不上 MCP（自家兄弟服务，MQTT 意图协议足够；MCP 仅在将来第三方 agent 接入时套适配器）。
- **分层复用**：butler（大脑）只发意图；zap-tv（手）干 adb 活并自证结果；doubao2api（多模态网关）远期供视觉/文生图/文生音乐。

## 3. MQTT 主题协议（单一真源：`butler/bus/topics.py`）

| 主题 | 方向 | 载荷 | 说明 |
|---|---|---|---|
| `tv/livingroom/experiment` | TV→butler | `{"type":"xiaoai_listening_end","recognized_text":"...","interrupted":true,...}` | 语音事件；**recognized_text 必须是用户语音文本**（修复后） |
| `tv/livingroom/control` | butler→zap-tv | `{"action":"zap","channel":"湖南卫视","request_id":"..."}` | 换台意图（request_id 必带） |
| `tv/livingroom/fongmi/control` | TV→zap-tv | `{"movieName":...,"initials":...}` | 飞牛TV 搜索（TV 端发布，zap-tv 执行固定 adb 序列） |
| `tv/livingroom/result` | zap-tv→butler | `{"ok":true,"channel":"中央二台","no":6,...,"request_id":"..."}` | 执行回执；**request_id echo** 用于匹配等待 |
| `tv/livingroom/cmd/tts` | butler→TV | `{"url":...,"volume":80}` | TTS 音频 URL 播放 |
| `tv/livingroom/cmd/xiaoai_set_keywords` 等 | zap-tv→TV | 配置 | 自愈重发打断配置 |
| `tv/livingroom/status` | TV | 在线状态（retained+LWT） | |
| `butler/status/state` | butler | 在线状态（retained+LWT） | |

**zap-tv action 集合**：`zap`（换台）、`fongmi_search`、`keyevent`、`tap`。

**zap 载荷字段**：`channel`（频道名或号，支持 cctv 归一化）；`request_id`（必带，回执原样 echo）。

**result 字段**：`ok` / `duplicate`（10s 内同参数意图被去重时 true）/ `channel` / `no`（频道序号，mytv 数字键）/ `warmed` / `fg` / `mytv_alive` / `request_id` / `_topic`。

## 4. 换台链路（时序）

1. 遥控器语音键 → Arcface 小爱聆听 → 识别文本
2. Arcface 命中唤醒词（豆包/管家/豆包管家）→ 打断小爱 → 发布 `experiment`（`interrupted=true` + 纯净识别文本）
3. butler `on_tv_voice` → LLM function-calling → `switch_channel({"channel":"中央二台"})`
4. butler `TVClient.zap`：生成 `request_id` → 发布 `control` → **异步等待 result（25s 超时）**
5. zap-tv：10s 去重检查 → 频道归一化（cctv2→中央二台）→ warmup（HLS 预热）→ 确保 mytv 前台 → mytv 存活保活 → 逐字符注入数字键（mytv 自动确认）→ 发布 `result`（echo request_id）
6. butler 收到匹配回执 → 工具返回"已切换到 中央二台（第6台）" → LLM 生成回复 → edge-tts → `cmd/tts` 电视播报

**关键参数**：
- 频道号 = `channels.json` 键序 + 1（1=深圳卫视、5=中央一台、6=中央二台…）
- mytv 数字键映射：`KEYCODE_0→7、1→8…9→16`（mytv debounce 自动确认，无需 ENTER）
- zap-tv 执行约 10s（warmup+按键+等待 `max(1,(4-位数))+3s`）；butler 等待超时 25s

### 5.2 zap-tv（v7，NAS `/vol1/1000/docker/zap_tv`）
| 改动 | 说明 |
|---|---|
| 意图队列 + worker 线程 | `on_message` 只做"去重判断+入队"（即时），worker 串行执行并回执——**去重窗口按消息到达时刻计算**，不被执行时长吞掉 |
| 幂等去重 | 10s 内相同 `(topic, action, channel/key/x/y)` 忽略，立即回执 `{"ok":true,"duplicate":true}` |
| request_id echo | 回执原样带回 |
| 频道归一化 `normalize_channel` | 别名（湖南台→湖南卫视、央视一套→中央一台…）+ cctv/央视数字（cctv2→中央二台） |

### 5.3 上一轮（语音识别根因，已在 APK）
- 聆听结束瞬间从小爱界面即时提取识别文本（防 OCR 覆盖）

- 状态机 waiting 分支修复、dump 轮询 500ms→1s、禁用无效截图循环（CPU 81%→降，mytv 不再被 LMK 杀）
