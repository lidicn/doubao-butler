# 记忆系统路线图

> 创建：2026-09-11
> 更新：2026-09-11（补充 MA 资源利用）
> 目标：从对话中自动学习用户习惯，投喂给豆包长期记忆，让管家越来越聪明。

---

## 核心原则：分工合作，不重复建设

| 分工 | memory-agent（MA） | 豆包管家 |
|------|-------------------|---------|
| **数据类型** | 物理世界（视觉、在场、作息） | 语言世界（对话、偏好、家庭成员） |
| **擅长能力** | 视觉分析、行为洞察 | 自然语言处理、设备控制 |
| **存储方式** | 时序数据库（时序事件） | SQLite（对话记录、记忆事实） |

**原则**：
- MA 已经有的能力，管家不要再做
- 管家只做自己擅长的（语言分析）
- 两边数据通过 API 对接，融合成完整用户画像

---

## 核心流程

```
对话存储（管家） ──┐
                   ├──→ 数据融合层 ──→ 记忆提取 ──→ 记忆审核 ──→ 记忆投喂
物理数据（MA） ──┘
```

### 2. 记忆提取（1 天）✅ 已完成（2026-09-11）

**目标**：LLM 定期分析对话 + MA 数据，自动提取用户习惯/偏好/家庭成员。

**已实现**：
- ✅ `butler/memory/extractor.py` MemoryExtractor 类
  - 从 chat_logs 拉最近 7 天对话（最多 300 条）
  - 从 MA 拉成员作息基线（best-effort，失败不阻塞）
  - 调 new_api（低温 0.2）稳定输出 JSON：preferences/family/events/habits 四类
  - 解析容错：去 markdown 代码块、找首尾 `{}`、坏 JSON 不崩
  - 去重：同类型 30 天窗口内完全匹配 + 包含匹配
  - 写入 memory_facts（status=pending，confidence 自动 clamp 到 0~1）
- ✅ 定时任务：每天 **03:15**（错开 3:00 自进化任务，避免 LLM 并发）
  - 注册到统一调度中心 `sched:memory_extract`
- ✅ 手动触发 API：`POST /api/memory/facts/extract/run` body `{"days":7}`
- ✅ 13 个单元测试全过（解析/截断/去重/CRUD/端到端）

**数据源**：

| 数据源 | 来源 | 提取什么 |
|--------|------|---------|
| 对话记录 | 管家 chat_logs 表 | 偏好、家庭成员、重要事件 |
| 在场数据 | MA `/api/vision/presence` | 谁在哪、什么时候活动 |
| 作息基线 | MA `/api/insights/member-schedule` | 什么时候起床、睡觉 |
| 行为洞察 | MA 待开发接口 | 习惯学习（早上7点看电视等） |

**什么时候跑？**
- 每天凌晨 3 点（用户睡觉的时候）
- APScheduler 定时任务

**管家自己分析（从 chat_logs）**：
```
分析最近 7 天的用户对话，提取以下信息：

1. 用户偏好（preferences）
   - 喜欢简洁的回复
   - 不喜欢被打扰

2. 家庭成员信息（family）
   - 凯文12岁，喜欢Xbox
   - 爱美丽10岁，喜欢听歌

3. 重要事件（events）
   - 9月12日要去医院复诊

输出 JSON 格式：
{
  "preferences": ["喜欢简洁的回复"],
  "family": [{"name": "凯文", "age": 12, "likes": "Xbox"}],
  "events": [{"date": "09-12", "title": "去医院复诊"}]
}
```

**从 MA 拉取（习惯类）**：
- 待 MA 提供行为洞察接口后对接
- 目前先从 presence + schedule 数据自己推断（简单规则）

**存到哪？**

- 状态：`pending`（待审核）/ `approved`（已确认）/ `rejected`（已拒绝）

```
【我的偏好 · 请存入长期记忆】
- 喜欢简洁的回复
- 不喜欢被打扰
```

**投喂到哪？**
