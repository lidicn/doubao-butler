## v1.1 — 数据隔离基础

**目标**：建立三层数据隔离，技能支持状态管理。

### 功能清单

| 功能 | 描述 | 验收标准 |
|------|------|---------|
| 目录隔离 | skills/ 分为 builtin/、user/、agent/ 三个子目录 | 现有技能迁移到对应目录，加载正常 |
| 技能状态 | 技能增加 status 字段：draft/enabled/disabled/quarantined | 状态变更正确持久化 |
| 来源标记 | 技能增加 source 字段：builtin/user/agent | 可按来源筛选技能 |
| 优先级 | 技能增加 priority 字段（1-100，默认50） | 高优先级技能先执行 |
| 存储扩展 | SkillStore 支持多目录加载、按状态过滤 | API 返回按目录/状态/来源筛选 |
| 热加载 API | POST /api/skills/reload 重新加载所有技能 | 调用后新技能立即生效，无需重启 |

### 数据迁移

- 现有 `data/skills/*.json` 迁移到 `data/skills/user/`（标记为 user 来源）
- 内置默认技能迁移到 `data/skills/builtin/`（标记为 builtin 来源）
- 迁移脚本自动执行，备份原文件

### API 变更

```
GET  /api/skills?source=user&status=enabled   # 按来源/状态筛选
POST /api/skills/reload                        # 热加载
GET  /api/skills/{id}/status                   # 查看状态
PUT  /api/skills/{id}/status                   # 修改状态
```

## v1.2 — 对话式创建

**目标**：用户通过自然语言描述，LLM 自动生成技能，用户确认后生效。

### 功能清单

| 功能 | 描述 | 验收标准 |
|------|------|---------|
| create_skill 工具 | Agent 工具：根据用户描述生成技能 JSON | LLM 能正确解析意图并生成合法 JSON |
| 技能草稿 | 生成的技能先存为 draft 状态，不生效 | draft 技能不会被触发 |
| 预览确认 | 用户可预览技能定义，确认/修改/取消 | 确认后状态变为 enabled |
| 自然语言解析 | 支持时间、事件、条件、动作的组合解析 | "每天7点看到Kevin说早上好"能正确生成 |
| 技能模板 | 常用场景模板（问候、提醒、监控、自动化） | 模板可一键生成基础技能 |
| 对话式修改 | 用户可自然语言修改已生成的技能 | "把时间改成8点"能正确修改 |

### 创建流程

```
1. 用户描述需求
2. LLM 生成技能 JSON（draft）
3. butler 回复预览："我理解你想要一个XX技能，触发条件是XX，动作是XX，确认吗？"
4. 用户确认/修改
5. 保存为 enabled，热加载生效
6. 回复："技能已创建并生效"
```

### 工具定义

```json
{
  "name": "create_skill",
  "description": "根据用户描述创建一个新技能。返回技能定义草稿，需用户确认后生效。",
  "parameters": {
    "type": "object",
    "properties": {
      "name": {"type": "string", "description": "技能名称"},
      "trigger": {"type": "object", "description": "触发条件"},
      "senses": {"type": "array", "description": "感官输入"},
      "brain": {"type": "object", "description": "处理逻辑"},
      "output": {"type": "array", "description": "输出动作"},
      "limits": {"type": "object", "description": "限制条件"}
    },
    "required": ["name", "trigger", "output"]
  }
}
```

## v1.3 — 自动隔离

**目标**：有问题的技能自动隔离，不影响系统运行。

### 功能清单

| 功能 | 描述 | 验收标准 |
|------|------|---------|
| 增强熔断 | 60s>5次触发→冷却，连续冷却3次→隔离 | 高频触发的技能自动隔离 |
| 失败隔离 | 连续3次执行失败→移入隔离区 | 失败技能不再被触发 |
| 超时控制 | 单次执行>30s自动终止，连续超时3次→隔离 | 卡死的技能被自动隔离 |
| 隔离区管理 | quarantined 状态技能不触发，保留7天 | 隔离技能可查看、恢复、删除 |
| 隔离原因记录 | 自动记录隔离原因、时间、相关日志 | 可查看每个隔离技能的详细原因 |
| 审计日志 | Agent 所有操作记录到 audit/actions.log | 创建/修改/删除/隔离都有记录 |
| 观察期 | 恢复的技能进入24h观察期，阈值减半 | 观察期内更严格的监控 |

### 隔离触发条件

```python
ISOLATION_RULES = {
    "frequency": {"window_s": 60, "max_hits": 5, "cooldown_base_s": 300},
    "failure": {"consecutive_failures": 3, "action": "quarantine"},
    "timeout": {"max_duration_s": 30, "consecutive_timeouts": 3, "action": "quarantine"},
    "resource": {"max_memory_mb": 100, "max_cpu_percent": 50, "action": "quarantine"},
    "dependency": {"missing_dependency": "disable", "action": "disable"},
}
```

## v1.4 — 版本管理

**目标**：技能修改可追溯、可回滚。

### 功能清单

| 功能 | 描述 | 验收标准 |
|------|------|---------|
| 版本历史 | 每次修改保存历史版本（最多20个） | 可查看任意历史版本 |
| 一键回滚 | 回滚到任意历史版本 | 回滚后技能立即生效 |
| 版本对比 | 两个版本之间的差异对比 | 可查看修改了哪些字段 |
| 自动备份 | 每日备份所有技能到 data/backup/ | 备份文件可恢复 |
| 备份保留 | 备份保留30天 | 超期自动清理 |
| 全量恢复 | 一键回滚到某天的完整状态 | 所有技能恢复到指定日期 |

### 版本存储结构

```
data/versions/skills/{skill_id}/
├── v1.json
├── v2.json
├── v3.json
└── manifest.json    # 版本列表、当前版本、修改记录
```

## v1.5 — 冲突检测

**目标**：多个技能同时触发时，按优先级有序执行，避免冲突。

### 功能清单

| 功能 | 描述 | 验收标准 |
|------|------|---------|
| 触发冲突检测 | 同一事件触发多个技能时，按优先级排序 | 高优先级先执行 |
| 输出冲突处理 | 多个技能同时播报时，按 on_busy 策略 | queue 模式排队，drop 模式丢弃 |
| 设备冲突检测 | 多个技能同时控制同一设备时，串行执行 | 设备操作不重叠 |
| 时间冲突检测 | 定时技能同一时间触发时，按优先级排序 | 不会同时执行 |
| 冲突告警 | 检测到频繁冲突时，通知用户 | 用户可查看冲突报告 |
| 优先级调整 | 用户可调整技能优先级 | 调整后立即生效 |

### 优先级规则

1. 安全相关（安防、告警、门锁）→ priority 90-100
2. 用户手动创建 → priority 60-80
3. Agent 生成 → priority 40-50（默认）
4. 实验性/娱乐 → priority 10-30

## v1.6 — 引擎插件化

**目标**：支持用户和 Agent 创建自定义引擎，沙箱安全运行。

### 功能清单

| 功能 | 描述 | 验收标准 |
|------|------|---------|
| 用户引擎安装 | data/plugins/user/ 目录的引擎自动加载 | 安装后无需重启即可使用 |
| Agent 引擎生成 | LLM 生成自定义引擎代码（需审核） | 生成的引擎在沙箱中测试 |
| 沙箱运行 | 引擎在受限 Python 环境中执行 | 不能访问文件系统、网络（除白名单） |
| 权限声明 | 引擎 manifest 声明所需权限 | 越权访问被拒绝 |
| 引擎市场 | 内置常用引擎模板 | 用户可基于模板创建 |
| 引擎测试 | 新引擎先在测试模式运行 | 测试通过后才能正式启用 |

### 引擎 Manifest

```json
{
  "id": "custom_engine",
  "name": "自定义引擎",
  "version": "1.0",
  "entry": "engine.py",
  "class": "Engine",
  "permissions": {
    "ha_services": ["light.turn_on", "switch.turn_on"],
    "ma_apis": ["/api/vision/presence"],
    "network": ["api.example.com"],
    "filesystem": "none"
  }
}
```

## v1.7 — 触发条件扩展

**目标**：支持复杂的条件组合，不再局限于单一触发入口。

### 功能清单

| 功能 | 描述 | 验收标准 |
|------|------|---------|
| 条件组合 | 支持 AND/OR/NOT 条件组合 | "7点-8点 AND 看到Kevin AND 工作日" |
| 时间条件 | 支持时间段、工作日/周末、节假日 | 时间条件正确判断 |
| 状态条件 | 支持设备状态作为触发条件 | "灯开着 AND 没人"→关灯 |
| 事件条件 | 支持多个事件组合触发 | "门铃响 AND 晚上"→开门口灯 |
| 依赖检测 | 技能依赖的设备/引擎不存在时自动禁用 | 依赖恢复后自动启用 |
| 条件测试 | 可模拟条件测试技能是否会触发 | 测试结果准确 |

### 条件 DSL

```json
{
  "trigger": {
    "entry": "condition",
    "condition": {
      "all": [
        {"type": "time", "range": ["07:00", "08:00"]},
        {"type": "event", "name": "face_seen", "params": {"member": "Kevin"}},
        {"type": "state", "entity": "binary_sensor.workday", "value": "on"}
      ]
    }
  }
}
```

## 风险与依赖

| 风险 | 影响 | 应对 |
|------|------|------|
| LLM 生成技能质量不稳定 | 用户体验差 | 模板库 + 用户确认 + 自动测试 |
| 技能数量过多导致性能下降 | 系统变慢 | 优先级调度 + 资源限制 + 性能优化 |
| 自定义引擎安全风险 | 系统被攻破 | 沙箱 + 权限声明 + 审核 |
| 用户不理解技能定义 | 不敢使用 | 自然语言预览 + 模板 + 教程 |
| 技能冲突难以排查 | 行为不可预测 | 冲突检测 + 执行日志 + 可视化 |

## 验收标准（每个版本）

1. **功能完整**：所有功能清单中的功能都实现并可演示
2. **测试通过**：单元测试覆盖率 >80%，集成测试通过
3. **文档齐全**：用户文档、API 文档、变更日志
4. **向后兼容**：现有技能和配置不受影响
5. **性能达标**：核心服务响应时间 <500ms，技能加载 <1s
6. **安全审计**：无已知安全漏洞，隔离机制有效
