# 交接单：监控对话重构为「技能+引擎」标准并实现单对话线程

- 日期：2026-09-05
- 负责人：butler（主导）/ dw（攻坚手，模式 A）
- 关联需求：「家庭监控画面人物分析」每次触发都开新对话（不积累上下文）→ 改为单对话线程；旧实现未走当前【技能+引擎】标准 → 按标准重构。

## 一、根因

"每次监控都开新对话"的根因不是 doubao2api 不支持续聊，而是**调用方没有带/复用稳定的 conversation_id**：

- doubao（字节）云端按 `conversation_id` 隔离对话线程；不带或每次带新 id 就会开新对话。
- 旧监控实现（NAS 上的旧部署）未走标准 `camera_vlm` 引擎的 `live_vlm` 模式，也就没走 `role_state` 的 conversation_id 复用逻辑。
- 真正聊天记录在豆包云端；本地只需要持有 `conversation_id` 指针（极小，存 `data/role_state.json`）。

   - `butler/roles/state.py`：`RoleConversationStore` 持久化 `{conversation_id, updated_at}` 到 `data/role_state.json`，`app.py` 启动 `load()` → **重启不丢线程，可续聊**；
   - `butler/skills/runner.py:140`：`ctx.role = rt.roles.resolve_for_skill(skill)`。
