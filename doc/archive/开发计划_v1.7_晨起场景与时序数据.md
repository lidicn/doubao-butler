## 一、P0-2 时序数据存储 + MA 作息规律复用（2天）

### 1.1 功能说明

SQLite 存储管家侧需要实时告警的数据：
- 用户位置历史（已存在 presence_history 表）
- 模式切换记录（日常/观影/睡眠/会客/离家）
- 设备异常事件（掉线/低电量/异常运行）
- 家电运行时长（冰箱/洗衣机/空调等）

**不自建**行为习惯学习，复用 MA `member-schedule` 作为先验置信度输入。

### 1.2 模块结构

```
butler/timeseries/
├── __init__.py          # TimeSeriesEngine 主类
├── store.py             # SQLite 存储（模式切换/设备异常/家电运行）
├── anomaly.py           # 实时异常检测引擎
└── api.py               # REST API 路由
```

### 1.3 数据模型

```python
# 模式切换记录
ModeTransition = {
    "id": INTEGER PRIMARY KEY,
    "mode": "sleep" | "movie" | "guest" | "away" | "daily",  # 模式名
    "action": "enter" | "exit",   # 进入/退出
    "ts": REAL,                    # 时间戳
}

# 设备异常事件
DeviceAnomaly = {
    "id": INTEGER PRIMARY KEY,
    "entity_id": TEXT,             # HA 实体 ID
    "type": "offline" | "low_battery" | "abnormal",  # 异常类型
    "severity": "info" | "warning" | "critical",
    "message": TEXT,
    "resolved": INTEGER DEFAULT 0,  # 0=未解决, 1=已解决
    "ts": REAL,
}

# 家电运行时长
ApplianceRuntime = {
    "id": INTEGER PRIMARY KEY,
    "entity_id": TEXT,
    "duration_minutes": REAL,       # 本次运行时长（分钟）
    "started_at": REAL,
    "ended_at": REAL,
}
```

### 1.4 MA 作息规律复用

- 调用 `GET /api/insights/member-schedule` 获取用户作息规律
- 作为定位融合的先验置信度输入（如"lidicn 工作日 23:00-7:00 通常在主卧睡眠"→ 提高主卧基础分）
- 作为异常检测的基准（如"lidicn 通常 7:30 起床，今天 9:00 还没起"→ 异常）

### 1.5 验收标准

- [x] 模式切换记录能正常写入和查询（2026-09-10 验证：enter/exit/current_mode）
- [x] 设备异常事件能正常写入和查询（store 层已实现，API 查询已验证）
- [x] 家电运行时长能正常记录（store 层已实现，API 查询已验证）
- [x] `/api/timeseries/modes` 返回模式切换历史（2026-09-10 验证）
- [x] `/api/timeseries/anomalies` 返回异常事件列表（2026-09-10 验证）
- [ ] MA member-schedule 能正常拉取（需 MA 侧接口可用，P0-3 实现时对接）

**实现说明（2026-09-10）**：

## 二、P0-3 实时异常检测（1天）

### 2.1 功能说明

对比 MA 作息规律 + 实时数据，实时检测异常并推送：
- 到点无活动（如工作日 9:00  lidicn 还在主卧且无活动 → 关怀提醒）
- 冰箱长时间未开（如 12:00 还没开 → 可能不在家或异常）
- 家电运行异常（如洗衣机运行超过 3 小时 → 可能故障）
- 设备掉线（关键设备如路由器/网关掉线 → critical 警报）

### 2.2 检测规则

| 规则 | 条件 | 动作 | 严重度 |
|---|---|---|---|
| 到点无活动 | 工作日 9:00 后用户仍在睡眠模式且无活动 | Bark 关怀提醒 | info |
| 冰箱未开 | 12:00 后冰箱门未开超过 6 小时 | Bark 提醒 | info |
| 家电超时运行 | 洗衣机/空调运行超过 3 小时 | Bark 警告 | warning |
| 关键设备掉线 | 路由器/网关/HA 本身掉线 | Bark critical + 小爱 TTS | critical |
| 模式异常 | 离家模式下检测到人体活动 | Bark 警报 | critical |

### 2.3 实现方案

- 在 APScheduler 上添加定时检查任务（每 15 分钟）
- 异常事件写入 timeseries 存储
- 推送渠道：Bark（默认），critical 级别加小爱 TTS
- 去重：同一异常 1 小时内只推送一次

### 2.4 验收标准

- [x] 到点无活动检测正常（2026-09-10 代码实现：工作日 9:00-11:00 + 睡眠模式 + lidicn 在主卧）
- [x] 家电超时运行检测正常（2026-09-10 实现并优化：只检测 climate/fan/vacuum/humidifier/water_heater 域，排除普通开关/插座/灯）
- [x] 异常事件写入存储（2026-09-10 实现：ts.record_device_anomaly）
- [x] Bark 推送正常（含去重，1 小时内同一异常只推一次，2026-09-10 实现）
- [x] critical 级别触发小爱 TTS（2026-09-10 实现：关键设备掉线/离家模式有人）
- [x] 每 15 分钟定时检查（2026-09-10 实现：APScheduler interval job）

**实现说明（2026-09-10）**：
- 新建 `butler/timeseries/anomaly.py`：AnomalyDetector 类，4 条检测规则
- 规则1 到点无活动：工作日 9:00-11:00 + 睡眠模式 + lidicn 在主卧（置信度≥0.6）→ info
- 规则2 家电超时：只检测 APPLIANCE_DOMAINS（climate/fan/vacuum/humidifier/water_heater/lawn_mower/siren），排除普通开关/插座/灯/指示灯 → warning
- 规则3 关键设备掉线：router/gateway/nas/ha 等关键词匹配 → critical + 小爱 TTS
- 规则4 模式异常：离家模式下检测到人体活动 → critical + 小爱 TTS
- 去重：同一异常 1 小时内只推送一次（_dedup_cache）
- 定时：APScheduler interval 15 分钟，id=anomaly_detector
- 优化：首次测试发现 133 个误报（普通开关/插座长期开启），已修复为只检测家电域

## 三、P0-1 科幻级晨起场景（2天）

### 3.1 功能说明

触发条件（同时满足）：
1. 睡眠模式退出
2. 毫米波雷达检测到人离开床铺并在卧室走动
3. 卧室灯光开启
4. 时间 6:00-10:00

→ 判定真正起床 → 小爱播报：
- 睡眠时长（从时序数据计算）
- 室内环境（温度/湿度/空气质量）
- 天气（今日天气）
- 日程（今日日程）
- 设备状态（冰箱/洗衣机/安防）
→ 主动问询"需要打开窗帘并启动早餐模式吗？"

### 3.2 实现方案

- trigger 规则层实现：监听睡眠模式退出事件 + 位置变化 + 灯光状态
- 播报内容组装：从各模块拉取数据
- 主动问询：播报后等待用户语音回复（小爱耳朵）
- 人不起床不播报：位置仍在主卧且无活动 → 不触发

### 3.3 验收标准

- [x] 起床触发条件判定正确（2026-09-10 实现：睡眠退出+不在主卧+6:00-10:00+当天去重）
- [x] 播报内容完整（睡眠时长/室内环境/天气/设备状态，2026-09-10 实现）
- [ ] 主动问询正常（需小爱耳朵配合，P1 迭代）
- [x] 人不起床不播报（2026-09-10 实现：仍在主卧且置信度≥0.7 时不触发）
- [x] 每天只播报一次（2026-09-10 实现：_morning_reported_date 去重）

**实现说明（2026-09-10）**：
- 新建 `butler/morning/` 模块（__init__.py/routine.py）
- MorningRoutine 类：check_and_broadcast() 检查 4 个触发条件
- 条件1：当前不是 sleep 模式 + 最近 4 小时内有 sleep exit
- 条件2：lidicn 不在主卧（或置信度<0.7）
- 条件3：时间 6:00-10:00
- 条件4：当天未播报过
- 播报内容：睡眠时长（从模式切换记录计算）+ 室内温湿度（HA）+ 天气（HA weather 实体）+ 设备异常摘要
- 推送：TTS 到主卧室音箱（xiao_touch8，小爱音色）+ Bark 文字推送（group=morning）
- 定时：APScheduler interval 5 分钟，id=morning_routine（只在 6:00-10:00 实际触发）
- 主动问询（"需要打开窗帘并启动早餐模式吗？"）留到 P1 迭代（需小爱耳朵双向交互）
