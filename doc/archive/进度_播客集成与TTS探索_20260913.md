## 背景

目标是获得接近 Audiomyst（百度 AI 播客）级别的拟真人音色，替代机械的 EdgeTTS，用于早晚简报播报。

## TTS 音色探索历程

### 已验证做不通的路线

| 方案 | 结果 |
|---|---|
| 百度短文本在线合成（per=0/1/3/4/5/103/106/110/111/5003/5118/4200/4203/4205/4206/4214/4217） | 跟 EdgeTTS 同级，不够拟真 |
| 百度大模型声音复刻 API（create） | 参数格式始终报 10005/11010，未跑通 |
| 百度端到端语音大模型 WebSocket | model_not_found，是对话模型不是纯 TTS |
| doubao2api /v1/audio/speech | TTS is disabled，用户说不用开 |
| NowVoice.ai | body 是二进制 octet-stream，逆向成本中等，效果比 EdgeTTS 好但比 Audiomyst 差 |
| Audiomyst 网页版 | 效果极好，但无公开 API，需手动生成 |

### 当前路线：豆包网页版 AI 播客 → doubao2api 集成

**原理**：豆包网页版本身有 AI 播客能力，发送"生成一段 X 分钟的 AI 播客，主题：xxx"指令，豆包自动生成双人对话播客。

**关键发现**（通过浏览器抓包 + 分享链接 JSON 解析）：

1. 播客通过普通对话触发，不是 `/samantha/chat/completion` 的专门 skill
2. 播客消息的 `content_type = 100`，`applet_id = com.flow.podcast`
3. 完整播客数据在 `widget_data.data.episodeList.episodes[0].meta.playback_model.audio_link`
4. **完整播客生成完成时**，`audio_link` 是 `https://p6-flow-sign.byteimg.com/...` 完整 URL，且有 `duration` 字段
5. **生成中**，`audio_link` 是相对路径 `/chat/podcast/chunk?resource_id=...`，且有 `waiting_reply` 字段

## 已完成的工作

### doubao2api 端点

- 端点：`POST /v1/audio/podcast`
- 请求参数：`topic`, `duration_minutes`, `voice_style`, `poll_interval`, `timeout`
- 流程：
  1. 通过 `chat_completion` 发送播客生成指令
  2. 轮询 `fetch_conversation_messages` 获取对话历史
  3. 解析 `content_type=100` 的助手消息
  4. 从 `widget_data` 提取 `audio_link`（仅接受 `https://` 开头的完整 URL）

### 修复的 bug

- `fetch_conversation_messages` 需要用 `async with DoubaoChatClient.from_session() as client:` 正确初始化
- `generate_podcast` 方法在第二个 `DoubaoChatClient` 类中（文件有两个同名类）
- 轮询条件：只有 `audio_link` 是 `https://` 开头才认为完成，相对路径说明还在生成中
