# 豆包管家自进化架构设计

> 版本：v1.0 | 日期：2026-09-07 | 状态：设计稿

## 一、设计目标

让豆包管家具备"对话式自进化"能力：用户通过自然语言描述需求，内置 LLM 自动生成触发规则、技能、引擎，热加载生效，且**不影响核心代码运行**。

核心原则：
1. **核心代码零侵入** — 自进化层完全独立，核心服务不受影响
2. **LLM 只生成声明式配置** — 不写 Python 代码，安全边界清晰
3. **数据三层隔离** — 核心代码 / 用户数据 / Agent 生成数据严格分离
4. **故障自动隔离** — 有问题的技能自动熔断、隔离、禁用
5. **用户确认制** — Agent 生成的内容必须用户确认后才生效

## 二、数据隔离架构

### 2.1 三层数据隔离

```
/app/
├── butler/                    # 【第一层】核心代码（只读，容器重建后恢复）
│   ├── core/                  #   agent, dialog, tools, state
│   ├── skills/                #   技能引擎框架 + 内置引擎（只读）
│   ├── integrations/          #   HA, MA, LLM, TTS, TV 集成
│   ├── api/                   #   HTTP 路由
│   └── decision/              #   决策层
│
└── data/                      # 【第二层+第三层】数据卷（持久化）
    ├── butler.db              #   用户数据：对话历史、日程、触发记录
    ├── roles/*.json           #   用户数据：角色配置
    ├── config.json            #   用户数据：全局配置
    ├── devices.json           #   用户数据：设备配置
    │
    ├── skills/                #   技能定义（按来源隔离）
    │   ├── builtin/           #     【内置】系统默认技能（只读，随版本更新）
    │   ├── user/              #     【用户】用户手动创建/修改的技能
    │   └── agent/             #     【Agent】LLM 自动生成的技能（需审核）
    │
    ├── plugins/               #   自定义引擎（按来源隔离）
    │   ├── user/              #     用户安装的引擎插件
    │   └── agent/             #     Agent 生成的引擎（需审核，沙箱运行）
    │
    ├── versions/              #   版本历史（技能/引擎的历史版本）
    │   ├── skills/
    │   └── plugins/
    │
    ├── quarantine/            #   隔离区：有问题的技能自动移入
    │   └── skills/
    │
    └── audit/                 #   审计日志：Agent 的所有操作记录
        └── actions.log
```

### 2.2 隔离规则

| 数据类型 | 存储位置 | 写入权限 | 生效条件 | 备份策略 |
|---------|---------|---------|---------|---------|
| 核心代码 | `/app/butler/` | 仅容器构建时 | 容器重启 | 镜像版本 |
| 用户配置 | `data/roles/`, `config.json` | 用户/API | 立即生效 | 每日备份 |
| 用户技能 | `data/skills/user/` | 用户/API | 立即生效 | 版本历史 |
| Agent 技能 | `data/skills/agent/` | 仅 Agent | **用户确认后** | 版本历史 + 审计 |
| 内置技能 | `data/skills/builtin/` | 仅系统更新 | 立即生效 | 随镜像 |
| 隔离技能 | `data/quarantine/skills/` | 自动/用户 | 不生效 | 保留7天 |
| 自定义引擎 | `data/plugins/user/` | 用户 | 重启后加载 | 版本历史 |
| Agent 引擎 | `data/plugins/agent/` | 仅 Agent | **用户确认 + 沙箱测试** | 版本历史 + 审计 |

## 三、技能生命周期与自动隔离

### 3.1 技能状态机

```
                    ┌─────────────┐
                    │   draft     │  Agent 生成，未审核
                    │  (草稿)     │
                    └──────┬──────┘
                           │ 用户确认
                           ▼
                    ┌─────────────┐
          ┌────────│   enabled   │─────────┐
          │        │  (已启用)    │         │
          │        └──────┬──────┘         │
          │               │                │
   用户禁用 │         触发异常          用户修改
          │               │                │
          ▼               ▼                ▼
    ┌──────────┐   ┌─────────────┐   ┌──────────┐
    │ disabled │   │ quarantined │   │ modified │
    │ (已禁用)  │   │  (已隔离)    │   │ (修改中)  │
    └──────────┘   └──────┬──────┘   └────┬─────┘
                           │               │
                    自动/用户恢复       重新审核
                           │               │
                           └───────┬───────┘
                                   ▼
                              回到 enabled
```

### 3.2 自动隔离触发条件

| 条件 | 阈值 | 动作 | 恢复方式 |
|------|------|------|---------|
| 触发频率过高 | 60s 内 >5 次 | 熔断冷却（300s 起指数退避） | 自动恢复 |
| 连续执行失败 | 连续 3 次失败 | 移入隔离区，状态 quarantined | 用户手动恢复 |
| 执行超时 | 单次 >30s | 终止执行，计数+1 | 连续超时3次→隔离 |
| 资源占用过高 | 内存 >100MB 或 CPU >50% | 终止+隔离 | 用户手动恢复 |
| 安全规则违规 | 调用危险服务 | 立即隔离+告警 | 需用户审核 |
| 依赖缺失 | 引擎/设备不存在 | 禁用并通知 | 依赖恢复后自动启用 |

### 3.3 隔离区机制

- 隔离的技能**不会被触发**，但保留定义和历史数据
- 隔离时自动记录原因、时间、相关日志
- 隔离区保留 7 天，超期自动清理（可配置）
- 用户可查看隔离原因，选择"恢复"或"删除"
- 恢复时自动进入 24 小时观察期，观察期内触发频率阈值减半

## 四、对话式创建流程

### 4.1 技能创建流程

```
用户："每天早上7点看到Kevin，就说早上好并播报天气"
  │
  ▼
LLM 意图解析
  ├─ 触发条件：schedule(07:00) + face_seen(Kevin)
  ├─ 感官：camera(客厅)
  ├─ 大脑：llm_text（生成问候+天气）
  ├─ 输出：tv_notify + xiaomi_speak
  └─ 限制：per_day=1
  │
  ▼
生成技能 JSON（draft 状态）
  │
  ▼
用户预览确认
  ├─ 确认 → 保存到 data/skills/agent/，状态 enabled
  ├─ 修改 → 用户编辑后重新确认
  └─ 取消 → 丢弃草稿
  │
  ▼
热加载生效（无需重启）
```

### 4.2 Agent 操作审计

所有 Agent 的创建/修改/删除操作都记录审计日志：

```json
{
  "timestamp": "2026-09-07T10:30:00",
  "action": "create_skill",
  "agent": "butler-core",
  "trigger": "user_request",
  "user_input": "每天早上7点看到Kevin说早上好",
  "skill_id": "morning_greeting_kevin",
  "skill_version": 1,
  "status": "draft",
  "user_confirmed": true,
  "review_notes": ""
}
```

## 五、运行时隔离与安全

### 5.1 技能执行沙箱

- 每个技能在独立的 asyncio 任务中执行
- 执行超时：默认 30 秒（可配置）
- 资源限制：单个技能并发数 ≤1，全局技能并发 ≤5
- 异常捕获：技能执行异常不影响主进程
- 调用链追踪：每次执行生成 trace_id，可追溯完整调用链

### 5.2 引擎插件安全

- 用户自定义引擎需通过 manifest 声明权限范围
- Agent 生成的引擎默认在沙箱中运行（受限 Python 环境）
- 引擎只能访问声明的资源（HA 服务、MA 接口等）
- 禁止文件系统写入（除指定临时目录）
- 禁止网络访问（除声明的白名单域名）

### 5.3 危险操作防护

以下操作需要用户二次确认：
- 控制门锁、安防设备
- 删除数据、清空历史
- 修改全局配置、角色配置
- 创建/修改其他技能
- 发送消息给家庭成员以外的人

## 六、冲突检测与优先级

### 6.1 技能冲突检测

- **触发冲突**：多个技能监听同一事件，按优先级执行
- **输出冲突**：多个技能同时播报，按 on_busy 策略（queue/drop）
- **设备冲突**：多个技能同时控制同一设备，串行执行
- **时间冲突**：定时技能在同一时间触发，按优先级排序

### 6.2 优先级规则

1. 安全相关技能（安防、告警）最高优先级
2. 用户手动创建的技能优先于 Agent 生成的
3. 明确指定优先级的技能（priority 字段）
4. 同优先级按创建时间排序（先创建先执行）

---

## 七、版本管理与回滚

### 7.1 技能版本

- 每次修改自动保存历史版本（最多保留 20 个版本）
- 版本号递增：v1 → v2 → v3
- 支持一键回滚到任意历史版本
- 回滚操作也记录审计日志

### 7.2 配置备份

- 每日自动备份所有技能和配置到 `data/backup/`
- 备份保留 30 天
- 支持全量恢复（一键回滚到某天的状态）

## 九、关键设计决策

### 9.1 为什么用 JSON 而不是 Python？

- **安全**：JSON 是声明式的，不会执行任意代码
- **可校验**：有 schema 校验，格式错误会被拦截
- **可版本化**：JSON 易于 diff、回滚、合并
- **用户可读**：用户可以理解和修改技能定义
- **LLM 友好**：LLM 生成 JSON 比生成 Python 代码更可靠

### 9.2 为什么需要用户确认？

- LLM 可能误解用户意图，生成不符合预期的技能
- 技能可能影响家庭设备运行，需要用户知情
- 用户确认是最后的安全防线
- 确认过程也是用户学习和理解的过程

### 9.3 为什么 Agent 不能直接修改核心代码？

- 核心代码的稳定性是管家的基础
- LLM 生成的代码质量不可控
- 核心代码修改需要完整测试，不适合热加载
- 核心代码变更应该通过正式开发流程

## 十、风险与应对

| 风险 | 影响 | 应对措施 |
|------|------|---------|
| LLM 生成错误技能 | 设备误操作 | 用户确认 + 隔离机制 + 危险操作二次确认 |
| 技能死循环触发 | 系统资源耗尽 | 熔断 + 频率限制 + 自动隔离 |
| 技能冲突 | 行为不可预测 | 冲突检测 + 优先级调度 |
| 自定义引擎安全漏洞 | 数据泄露/系统被攻破 | 沙箱运行 + 权限声明 + 白名单 |
| 版本回滚导致数据不一致 | 技能行为异常 | 回滚时校验依赖 + 数据迁移 |
| 审计日志泄露隐私 | 隐私风险 | 日志脱敏 + 本地存储 + 定期清理 |

## 十一、未来扩展方向

1. **技能市场**：用户可以分享和下载技能
2. **技能模板**：常用场景的技能模板，一键生成
3. **自然语言调试**：用户用自然语言描述问题，LLM 自动修复技能
4. **技能性能分析**：分析技能的触发频率、成功率、资源占用
5. **跨家庭技能同步**：多家庭之间同步技能配置
6. **技能 A/B 测试**：同一需求多个技能版本，对比效果
