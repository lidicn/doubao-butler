# 豆包管家 v1.9 — Koin Action【智动】

> 创建：2026-09-14
> 主题：技能平台统一底座 — 新增 `cron_task` 引擎，支持定时条件任务
> 定位：资讯类任务编排子系统，复用技能平台所有基础设施

---

## 一、核心概念

**什么是 Koin Action【智动】？**

用户用自然语言描述需求（如"这是彩云天气 API，如果今天中午/下午/晚上有雨，早上 7:20 通过客厅小爱提醒我"），Koin（LLM）自动解析成结构化任务 JSON，定时执行，条件满足时推送/TTS。

**核心设计：技能平台统一底座**

Koin Action 不是独立系统，而是**技能平台的一个新引擎类型**：

| 类型 | 引擎 | 触发方式 | 用途 |
|---|---|---|---|
| 普通技能 | `llm_text` / `static_text` / `tool_sequence` | 事件驱动（人脸/语音/按钮） | 设备联动、家庭自动化 |
| Koin Action | `cron_task`（新引擎） | 定时驱动（cron） | 资讯类任务、信息推送 |

**核心价值：**
- 用户自己定义业务逻辑，不需要开发者改代码
- 复用技能平台所有基础设施（Schema 校验/沙箱测试/版本管理/WebUI/执行日志/失败告警）
- 统一管理：所有技能（包括 Koin Action）在同一个 WebUI 里管理
- 统一自进化：Koin Action 的执行结果也可以被自进化引擎学习

## 三、API 注册层（用户预配置）

**功能：**
- 用户在 WebUI 里预注册常用 API（彩云天气、新闻、股票等）
- 每个 API 包含：名称、URL 模板、密钥（Secret Vault）、示例响应、描述
- LLM 只能从已注册的 API 里选择

**数据表：`koin_apis`**
```sql
CREATE TABLE koin_apis (
    id TEXT PRIMARY KEY,           -- caiyun_weather
    name TEXT NOT NULL,            -- 彩云天气
    base_url TEXT NOT NULL,        -- https://api.caiyunapp.com/v2.7/{token}/{lat},{lon}/weather
    secret_key TEXT NOT NULL,      -- 存在 Secret Vault
    sample_response TEXT,          -- 预拉取的示例响应（JSON）
    description TEXT,              -- 彩云天气 API，支持实时天气、小时预报、天预报、预警
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

**API 元数据缓存机制（解决 LLM 瞎写 JSONPath）：**
- 每一个 registered_api 缓存一份最新 response schema
- 用户自然语言生成任务时，自动把 API 真实结构喂给 LLM
- LLM 不再猜字段、不再猜下标，只基于真实 JSON 结构生成条件
- 根治：LLM 幻觉写错路径、时区错位下标错误、字段更新导致任务失效

## 四、Phase 1 — 原型（3-4 天）

**目标：** 验证「自然语言生成定时条件任务」核心闭环

### 4.1 新增 `cron_task` 引擎 — 1天

**功能：**
- 新引擎类型：`cron_task`
- 触发方式：cron 定时触发
- 条件判断：HTTP API 调用 + JSONPath 条件
- 动作执行：TTS / Bark 推送

**技能 JSON 示例：**
```json
{
  "id": "rain_reminder",
  "name": "早上7:20下雨提醒",
  "engine": "cron_task",
  "enabled": false,
  "room": "客厅",
  "brain": {
    "trigger": {
      "type": "cron",
      "cron": "20 7 * * *"
    },
    "condition": {
      "type": "api_call",
      "api_id": "caiyun_weather",
      "params": {
        "lat": "113.869565",
        "lon": "22.666851"
      },
      "check": "$.result.hourly.precipitation[12].probability > 50 || $.result.hourly.precipitation[18].probability > 50"
    },
    "action": {
      "type": "tts",
      "text": "今天中午或下午可能会下雨，出门记得带伞"
    }
  }
}
```

**复用现有基础设施：**
- ✅ Schema 校验（技能平台已有）
- ✅ 沙箱测试（技能平台已有）
- ✅ 版本管理（技能平台已有）
- ✅ WebUI 管理（技能平台已有）
- ✅ 执行日志（技能平台已有）
- ✅ 失败告警（技能平台已有）

### 4.2 API 注册页（WebUI）— 0.5天

**功能：**
- API 列表：已注册的 API
- 新增 API：名称、URL、密钥、描述
- 编辑/删除 API
- 测试 API：点击测试按钮，验证 API 是否可用

### 4.3 静态校验器扩展 — 0.5天

**功能：**
- cron 语法校验：cron 表达式合法性
- JSONPath 预编译校验：JSONPath 表达式语法
- URL 白名单校验：只允许调用已注册的 API
- SSRF 防护：禁止内网地址（127.0.0.1、192.168.x.x、10.x.x.x）

**条件短路保护（防御式表达式）：**
- 所有 check 表达式强制包裹存在性前置判断
- LLM 自动生成防御式表达式：
  ```
  $ && $.result.hourly && $.result.hourly.precipitation.length > 20 && $.result.hourly.precipitation[12].probability > 50
  ```
- 杜绝空指针、数组越界

**HTTP 层幂等契约（对齐 Forge 适配器）：**
- 适配器层只做单次请求、无重试、无超时策略
- 重试、超时、降级、兜底全部由 Koin 任务语义层控制
- 强制规则写入静态校验器

**校验失败处理：**
- 拒绝保存任务
- 返回错误信息给用户
- 提示用户修改描述

### 4.4 任务预览 + 用户确认 — 0.5天

**功能：**
- 生成任务 JSON 后，LLM 生成自然语言预览
- 向用户展示：「每天早上 7:20 查询彩云天气，如果今日 12 点/18 点/20 点降水概率 > 50%，客厅小爱音箱播报提醒」
- 用户确认 ✅，才写入数据库
- 用户可编辑修改生成的 JSON

**默认状态：**
- 任务创建后默认【禁用】
- 用户手动启用后才开始执行

### 4.5 任务执行引擎 — 0.5天

**功能：**
- APScheduler 定时触发
- HTTP 请求（使用 Secret Vault 引用，超时 10s）
- JSONPath 提取字段，条件判断
- 条件满足 → TTS 播报

**任务状态机（对齐 Forge IR 思想）：**
```
idle（空闲） → running（执行中） → success（成功）
                              ↘ failed（失败）
```
- 四态机：idle / running / success / failed
- 连续失败检测：连续 N 次 failed → 自动告警
- 任务健康度面板：成功率、平均执行时间

## 五、Phase 2 — 稳定版（2-3 天）

**目标：** 安全、审计、可靠性补齐

### 5.1 Secret Vault 完整版 — 0.5天

**功能：**
- 独立密钥存储，和任务 JSON 分离

**功能：**

- 自动 Bark 推送通知用户：「你的「下雨提醒」任务连续失败」

**功能：**
- 同一设备 TTS 消息排队

- 按优先级排序（紧急任务优先）

### 5.4 时区标准化 — 0.5天

**功能：**
- 所有 API 返回时间统一转本地时区
- LLM 不再手动猜数组下标

### 5.5 任务冲突熔断 — 0.5天

**功能：**
- 全局 API 调用节流器
- 同一 api_id 10s 内最多 1 次请求
- 超额直接跳过、标记节流、写入审计
- 防止高频轰炸第三方 API，避免 IP 限流/封禁

### 5.6 手动试运行按钮 — 0.5天

**功能：**
- WebUI 点击「测试运行」
- 立刻执行一次条件判断 + 模拟/真实动作
- 用于调试，不用等到定时时间

## 七、安全边界

### 7.1 ✅ 好的隔离

- Koin 是技能平台的一个引擎，和其他技能共享基础设施
- Koin 无权直接下发 HA 设备控制指令
- Koin 只能调用：TTS 播报接口、Bark、HTTP 白名单 API
- 豆包管家核心调度器完全不依赖 Koin，Koin 崩溃不影响全屋自动化

### 7.2 ⚠️ 边界红线（硬性禁止）

- Koin 任务不允许直接写实体状态、触发 HA 自动化
- HTTP 调用必须白名单，禁止任意内网地址（SSRF 防护）
- API 密钥绝对不能明文存在任务 JSON，单独存入 Secret Vault

## 十一、ha_claw 借鉴改进（v1.9+）

> 来源：https://github.com/ha-china/ha_claw
> 调研日期：2026-09-14
> 核心理念：不是"更聪明的遥控器"，而是"系统运维助手"

### 11.1 最小 Token 原则 ⭐⭐⭐⭐⭐ — P0（1天）

> "简单的事情不走 LLM，复杂的事情少走弯路"

**现状问题：** 所有工具调用都走 LLM，太浪费 token，延迟也高

**改进方案：**
- 明确命令（开灯、关空调、调音量）走**本地规则匹配** — 零 token、更快、更稳定
- LLM 只在需要判断、排查、创建、验证时才激活
- 长对话超过阈值时先压缩上下文再继续

**实现方式：**
```
用户输入 → 规则匹配层
  ├─ 匹配到明确指令（"开灯"）→ 直接执行，零 token
  └─ 未匹配 → 走 LLM 推理
```

**优先级：** P0（立即做）

---

### 11.2 任务系统（多步工具调用）⭐⭐⭐⭐⭐ — P0（3天）

> "每条消息都是一个任务，不是一个命令"

**现状问题：** 单步工具调用，做不了复杂任务

**改进方案：**
- 任务可以：连续读状态 → 调工具 → 检查结果 → 下一步
- 工具失败了会尝试其他路径
- 模型不够了会切换备份 agent
- 需要确认时会暂停并解释为什么

**任务执行循环：**
```
任务开始
  ↓
读当前状态
  ↓
LLM 决定下一步
  ├─ 完成 → 返回结果
  ├─ 需要工具 → 调用工具 → 检查结果 → 继续
  └─ 需要确认 → 暂停 → 等用户确认 → 继续
```

**优先级：** P0（Plan 模式的基础）

### 11.3 自进化 + 人工批准 ⭐⭐⭐⭐ — P1（2天）

> "它成长，但控制权在你手里"

**现状问题：** 自进化 tab 已经有了，但不够完善

**改进方案：**
- 任务完成后系统审查执行
- 如果经验值得保留，提议修改 Skills/Guides/Memory
- 如果技能堆积、重复或过时，提议清理
- **所有自进化都需要人工批准**

**自进化流程：**
```
任务完成
  ↓
审查执行结果
  ↓
有值得学习的经验？
  ├─ 是 → 提议修改（Skill/Guide/Memory）
  │    ↓
  │    用户确认？
  │    ├─ 是 → 应用修改
  │    └─ 否 → 丢弃
  └─ 否 → 结束
```

**优先级：** P1

### 11.4 经验保留 / MemoryGraph ⭐⭐⭐⭐ — P1（2天）

> "从失败中学习，下次避免同样的错误"

**现状问题：** 记忆系统有，但没有经验图谱

**改进方案：**
- 记录长期事实、决策、维修经验及其关系
- 下次遇到类似问题时，直接走最短路径
- 记忆节点之间有边（关系）

**MemoryGraph 结构：**
```
节点类型：
  - 事实（"书房灯经常闪烁"）
  - 决策（"上次换了驱动板就好了"）
  - 经验（"这个问题按这个步骤修"）

边类型：
  - 导致（事实 → 决策）
  - 相关（经验 ↔ 事实）
  - 时间（上次发生时间）
```

**优先级：** P1

---

### 11.5 多 agent 故障转移 ⭐⭐⭐ — P2（1天）

> "主模型失败时，自动切换到备份 agent 继续"

**现状问题：** LLM 调用失败就直接报错

**改进方案：**
- 主模型超时/失败 → 自动切换到备份模型
- 不需要人工干预，任务继续执行
- 记录失败原因，用于后续优化

**故障转移策略：**
```
调用主模型（DeepSeek）
  ├─ 成功 → 返回结果
  └─ 失败（超时/错误）
       ↓
     切换备份模型（豆包）
       ├─ 成功 → 返回结果 + 记录故障
       └─ 失败 → 最终报错
```

**优先级：** P2

---

### 11.6 动态 AI 实体 ⭐⭐ — P2（1天）

> "把 AI 判断和任务状态变成 HA 实体"

**现状问题：** AI 的判断结果不能被其他自动化引用

**改进方案：**
- 把感知结果、安全告警、任务状态变成 HA 实体
- 其他自动化可以引用这些实体

**实体示例：**
| 实体 | 类型 | 说明 |
|---|---|---|
| `sensor.butler_perception_state` | sensor | 当前感知状态（客厅有人/书房有人） |
| `binary_sensor.butler_security_alert` | binary_sensor | 安全告警（门窗未关） |
| `sensor.butler_task_running` | sensor | 当前运行的任务 |
| `button.butler_run_smoke_test` | button | 手动触发冒烟测试 |

**优先级：** P2
