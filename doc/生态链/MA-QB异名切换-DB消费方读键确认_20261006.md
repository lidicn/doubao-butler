### 3.2 每个工具实际读取的返回字段

```

  - [].id
  - [].content

  - [].created_at

  - objects[] (可选)

  - ok

  - members[].id
  - members[].name

  - ok

  - summary.median_last_seen

  - members[].last_seen
```

### 3.3 是否依赖 legacy 特有行为

- [ ] 依赖 legacy 的字段命名（Q-A 体系），新实现字段名不同会导致解析失败
- [ ] 依赖 legacy 的默认值/空值处理
- [ ] 依赖 legacy 的错误返回格式
- [x] **不依赖，只按 MCP schema / API 文档解析**
- [ ] 其他（请注明）

**说明**：butler 对所有 MA 响应都用 `_unwrap()` 做了容错（兼容 `{ok,data:{...}}` 和直接对象两种形态），字段缺失时返回空列表/空 dict 而非崩溃。但 `retrieve_agent_memories` 和 `ask_memory` 的返回是纯文本/字符串列表，若 Q-B 新实现改变了返回结构（如从字符串变成对象），会导致 butler 拿到空结果。

### 3.4 切换窗口期

> DCD 裁定切换后保留 7 天双跑。butler 是否能接受？是否有特定时间窗口偏好？

**butler 可接受 7 天双跑**，无特定时间窗口偏好。

**但需注意**：butler 当前**未直接调用** MA 文档列出的 4 个工具（get_user_persona/get_data_quality/data_coverage/get_device_usage），这些工具的 Q-B 切换对 butler **零影响**。

butler 实际调用的 MCP 工具（list_agent_memories/retrieve_agent_memories/ask_memory/add_semantic_memory/revoke_memory/get_vision_status/analyze_camera）若涉及 Q-B 异名切换，需 MA 侧在双跑期确保：
1. 工具名不变（butler 硬编码了工具名字符串）
2. 返回结构不变（特别是 retrieve/ask_memory 的纯文本返回）
3. 入参 schema 不变（特别是 retrieve_agent_memories 的 member_id 必填约束）

若以上任一点变化，butler 需同步改代码，建议 MA 侧提前通知。
