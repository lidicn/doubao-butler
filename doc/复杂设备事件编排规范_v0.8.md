# 复杂设备事件编排规范（v0.8）

> 创建：2026-09-06
> 适用：豆包管家（doubao-butler）+ Node-RED 设备层

---

## 一、分层原则

豆包管家采用**四层触发模型**，NR 只负责最底层的设备 IO：

```
┌─────────────────────────────────────────┐
│  应用层：豆包管家（butler 容器）          │
│  - 角色/人设/多轮对话/记忆               │
│  - LLM 推理/工具调用/技能执行            │
│  - Trigger 规则层（简单触发）            │
│  - 决策层/心跳（v0.9）                   │
├─────────────────────────────────────────┤
│  设备层：Node-RED（豆包管家 tab）        │
│  - 小爱对话监听 → butler /api/wakeup     │
│  - 复杂设备事件编排（多设备联动）         │
│  - 协议转换（MQTT ↔ HA ↔ HTTP）          │
├─────────────────────────────────────────┤
│  设备层：Home Assistant                   │
│  - 设备状态/服务调用                      │
├─────────────────────────────────────────┤
│  物理设备：小爱音箱/电视/传感器/按钮      │
└─────────────────────────────────────────┘
```

---

## 二、什么该写 butler trigger，什么该写 NR flow

### 2.1 写 butler trigger（简单触发）

**特征**：单事件 → 单技能（或短动作链），逻辑可用 JSON 规则表达。

| 场景 | 事件 | 动作 | 实现 |
|------|------|------|------|
| 早上看到 Kevin 打招呼 | face_detected | greet 技能 | butler trigger |
| 按钮按一下识别食物热量 | button_pressed | camera_vlm + 小爱播报 | butler trigger |
| 提醒到点全屋找人 | scheduled | locator + 小爱播报 | butler trigger |
| 语音说"创建规则" | voice_wake + text_contains | trigger_creator 技能 | butler trigger |
| 语音唤醒豆包管家 | voice_wake | agent 对话 | butler（耳朵层） |

**butler trigger 优势**：
- 可视化管理（/api/triggers CRUD）
- 执行日志可查（trigger_runs 表）
- 支持 LLM 生成（自我编排 v0.7）
- 容器重启不丢（JSON 文件持久化）
- 角色感知（哪个角色在哪个房间）

### 2.2 写 NR flow（复杂设备事件）

**特征**：多设备联动、协议转换、时序控制、状态机，逻辑难以用 JSON 规则表达。

| 场景 | 为什么用 NR |
|------|------------|
| 全屋小爱对话监听 → butler | 9 个小爱音箱的 conversation 传感器，NR trigger-state 节点天然支持 |
| "观影模式"：关灯+拉窗帘+开电视+调音响 | 多设备时序联动，NR 节点串联直观 |
| MQTT 传感器 → HA 服务调用 | 协议转换，NR 有成熟 MQTT/HA 节点 |
| 设备状态变化 → 条件判断 → 多分支 | NR switch/function 节点灵活 |
| 门铃响 → 拍照 → 推送 → 可选开门 | 多步骤异步流程，NR 适合 |

**NR flow 优势**：
- 设备 IO 成熟（HA websocket、MQTT、HTTP）
- 可视化拖拽，调试方便
- 适合复杂时序和状态机
- 不占用 butler 的 LLM 资源

### 2.3 判断流程

```
新需求来了
  │
  ├─ 是单事件→单技能吗？
  │   └─ YES → butler trigger
  │
  ├─ 涉及多设备联动/时序吗？
  │   └─ YES → NR flow（豆包管家 tab）
  │
  ├─ 需要 LLM 推理/角色人设/记忆吗？
  │   └─ YES → butler（NR 只做事件转发）
  │
  └─ 需要用户自然语言创建吗？
      └─ YES → butler trigger_creator（v0.7）
```

## 三、NR 豆包管家 tab 规范

### 3.1 命名规范

- flow 名称：`[来源] 事件描述 → 目标`
  - 例：`全屋小爱对话 → butler 耳朵转发`
- 节点名称：动词+宾语，中文
  - 例：`监听全屋小爱对话`、`提取文本+房间+唤醒词过滤`
- comment 节点：每个 flow 开头放一个 comment，说明用途、触发条件、输出

### 3.2 与 butler 的交互约定

NR → butler：
- 耳朵唤醒：`POST http://192.168.2.200:8095/api/wakeup`
  - body: `{"text": "...", "room": "客厅", "device": "xiao_living", "role": "butler"}`
- 通用事件：`POST http://192.168.2.200:8095/api/event`
  - body: `{"type": "button_pressed", "button_id": "...", "room": "..."}`

butler → NR：
- butler 不直接调用 NR，而是通过 HA 服务调用设备
- 如果需要 NR 执行复杂流程，butler 可以发布 MQTT 消息触发 NR flow

### 3.3 禁止事项

- ❌ 不在 NR 里写 LLM 调用（已迁移到 butler /api/llm/chat）
- ❌ 不在 NR 里写角色人设/多轮对话（butler 负责）
- ❌ 不在 NR 里写 trigger 规则（butler trigger 负责）
- ❌ 不在豆包管家 tab 里放与豆包管家无关的 flow

## 四、设备层确认（v0.8 验证）

### 4.1 小爱 TTS 播报

- 通道：HA `notify.send_message` → 小爱音箱 execute_text_directive
- 设备：9 个小爱音箱（DeviceRegistry）
- 队列互斥：同一设备同时只有一条 TTS（HA 原生队列）
- X08A 特殊：edge-tts 无限循环已修复（stop 替代清空列表，延迟 800ms）

### 4.2 HA 服务调用

- 通道：butler HAClient → HA REST API
- 常用服务：`media_player.play_media`、`notify.send_message`、`light.turn_on/off`
- 验证：v0.3 morning_lidicn trigger 的 tv_turn_on/tv_switch_channel 已真机验证

### 4.3 发声路由

- butler 根据 trigger 的 role + room 选择 output_device
- 角色配置：`data/roles/*.json` 的 output_devices 字段
-  fallback：如果指定房间设备不可用，用客厅主音箱

### 4.4 MQTT 事件总线

- 地址：192.168.2.200:1883（user=butler）
- butler 订阅：`butler/event/#`（voice/button/face/device_state）
- NR 可发布到 `butler/event/#` 触发 butler trigger

## 五、autoflow MCP 链路（v0.8 验证）

### 5.1 目标

用户跟豆包管家说"帮我创建一个自动化：每天晚上 10 点关灯"，butler 通过 autoflow MCP 创建 NR flow。

### 5.2 链路

```
用户语音 → butler 耳朵 → butler agent → LLM 工具调用
  → autoflow MCP Server → 生成 NR flow JSON → NR Admin API 导入
```

### 5.3 当前状态

- autoflow 项目已存在（E:\NAS\autoflow）
- MCP Server 待对接（v0.8 验证可用性）
- butler 侧需新增 autoflow 工具（v0.9 决策层 suggest_automation 时调用）

### 5.4 验证步骤

1. 确认 autoflow MCP Server 可启动
2. 确认 MCP 工具列表包含 create_flow/delete_flow
3. butler 调用 MCP 创建一个简单 flow（如"每天 22:00 关灯"）
4. NR 里能看到新 flow 并正常执行
