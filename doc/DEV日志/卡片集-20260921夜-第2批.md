### 问 1 · 盐从哪个键读、缺盐／空盐走哪条死路

**键**：新增 `TTS_CACHE_SALT` → `Settings.tts_cache_salt`（字段区放 `butler/config.py:170` 那一段 `tts_*` 里，与 `tts_cache_enabled` 同族）。读取仍用现成的 `_env`，但**第二个参数不传**：`tts_cache_salt=_env("TTS_CACHE_SALT")`。

**把关不靠默认值，靠门**：在 `Settings.load()` 现有三门之后追加第四门，形状照抄 `butler/config.py:284` 那段（它自己的注释写着「WO-BUT-022 R-37: web_password 空串=整站免鉴权，启动拒绝」）：

    if not s.tts_cache_salt:
        raise RuntimeError("TTS_CACHE_SALT is required but not set. Empty salt keeps cache filenames unsalted (= no protection).")

**死路表（三种输入 → 同一个结局）**：`_env` 的实现是 `os.environ.get(key, default).strip()`（`config.py:13-14`），所以「键不存在」「键在值为空串」「值只有空格」这三态**都**收敛成 `""` → `if not` 命中 → `raise` → **uvicorn 起不来**（`Dockerfile:29` 是 `CMD ["uvicorn","butler.app:app",...]`）。也就是说：这三态在运行时**不可区分**，所以不能靠"读出来像不像空"来判断，只能靠门。

**为什么结局必须是"起不来"而不是"退化成无盐"**：退化在现网上**完全不可见**（文件名仍是 40 位十六进制、HTTP 仍返回 200、日志不会说"我这一步没加盐"）；而起不来会在 `docker ps` / `docker logs` 上立刻可见。**一条只有失败才可见的开关，必须让它失败得可见**，否则它就是一个默认开着的安全洞（我台账里那条「安全开关三落点：配置／下发物／代码默认——fail-open 藏在第三个」说的正是这件事）。

**⛔ 三条禁止形（写出来就是为了实现单不许这么干）**：
1. `tts_cache_salt=_env("TTS_CACHE_SALT", "<任何字面量>")` —— 盐在镜像里＝盐公开，攻击者从源码或 `docker build` 产物就能拿它重算全部文件名，这是"fail-open 加一层皮"，比不加更坏（它会让验收报告写"已加盐"）。
2. 空盐时 `salt = salt or "default"` / `if not salt: return 旧算法` 这类回退梯 —— 同上，且它把 fail-open 藏进了表达式。
3. 只在**首次合成时**检查盐 —— 那 `/tts` 挂载（`app.py:232`）在检查之前就已经挂上了；门必须在 `Settings.load()`，即在建 app 之前。

**代价（不能只报安全）**：新增一把硬门＝**新增一条 `up -d` 崩回路**——`.env` 忘加这一把键，整站起不来（不是"只影响 TTS"）。DZ-6 现读支撑这条风险不是假想：镜像盘 `.env` 里有 **12 把键"写了等于没写"**（值 == 源码默认），另有 `MEMORY_AGENT_USER`/`MEMORY_AGENT_PASS` **两把键根本不存在**；而这套 `.env` 里存在 **len=5** 的口令、且有 `*_USER == *_PASSWORD` 的先例。⇒ 落地前置条件不是"能不能加门"，而是**先确认部署树 `.env` 里这把键已经填了足够长的值**。这一格我无 SSH，**现网未验**。窗口内一条只读把这一格钉死（⛔ 只出布尔，⛔ 不许 print 值）：

    docker exec <容器名> python -c "import os;print(bool(os.environ.get('TTS_CACHE_SALT','').strip()))"

**长度下限（要你裁，第 5 格点 2）**：建议门里再加 `len(s.tts_cache_salt) < 16` 也 `raise`。理由同上——这套 `.env` 已经证明会出 len=5 的口令，而盐的强度模型比口令更苛刻（口令要在线猜，盐是**离线枚举**：播报文本本身就是候选集，家庭场景文本量小，短盐可被暴力配对）。⛔ 我不规定盐长什么样，也不看它的值。

**「盐为空时探针应该看到什么」**：`TTS_CACHE_SALT=""`（合成串）下 `Settings.load()` 抛 `RuntimeError`、`python -c` 那条 rc != 0。**判红条件**：rc == 0 且 `s.tts_cache_salt == ""`——那就是本问的 fail-open，也是你红线里"默认值兼容旧行为"的实现形态。

### 问 2 · 旧 220 条文件名的作废代价

**先纠一个前提**（这个问题问得对，但它隐含的模型不成立）：**盐不参与"读已有文件"**。`_cache_hit`（`manager.py:47-62`）拿盐算一个新名字、然后 `path.exists()`（`:53`）——旧文件不匹配这个新名字，于是**被当作 miss**，引擎重新合成一份盐名件（`edge_tts.py:59`／`kokoro.py:34`／`nowvoice_tts.py:84` 各自写盘）。所以：
- **不存在"同时接受新旧两种名"这种过渡期**——没有任何开关在"接受旧名"，旧名只是**留在目录里的历史文件**，它们之所以还能被下载，是因为 `/tts` 这个 Mount **根本不看名字来源**（`StaticFiles` 只按路径取件）。⇒ "过渡期＝盐没生效"这个担忧在这一版设计里不适用；真正的风险是另一件事：**旧名可被离线重算，且重算旧名不需要盐**（旧算式无盐、公开在源码里）。
- 逐条代价（能量化的量化，量不了的标未量）：

| 代价 | 多大 | 多久自然消化 | 读数来源 |
