### runner 为什么能收 async 且**不新增依赖**
1. **没装任何东西**：容器里 `import pytest` 一定失败（`requirements.txt` 里 pytest 命中 **0**；`Dockerfile:15/19/22` 只 COPY requirements / vendor/homesdk / `butler/` ⇒ `tests/` 和 pytest 都不在镜像里）。runner 起时先试 `import pytest`，**成功就不碰**（本机开发态）；**失败才装替身**，只覆盖仓内实际用到的两个 API —— 实测全仓 pytest API 面就这两个：
   `pytest.mark.asyncio` 7 处（全在 `test_nas_ops_tools.py:193-232`）、`pytest.fixture` 1 处（`test_api_core.py:9`）。
2. **替身不假装支持别的**：`BARE_MARKS={"asyncio"}` 之外的 mark，无论裸用还是带参（`parametrize` 之类）一律抛 `_UnsupportedMark` ⇒ 模块进 `unsupported_marks` 名单 ⇒ **判红**，绝不多跑一次少报一次。已用合成夹具验咬合：`@pytest.mark.parametrize` → `unsupported_marks=1 / ran=0 / rc=1`（不是"跑一次蒙过去"）。
3. **需要 fixture 的不猜**：签名里有无参必填项 ⇒ `needs_fixtures` 名单 + 点名，不空跑不假跑（本轮 11 条，见 §五）。
4. **TestCase 里的协程**（当前 0 条，但这是 ①② 的假绿通道）：单独包出来跑，记 `testcase_async_rebased=N`，N>0 时也保证被 await。

### 事件循环隔离（对应仓内已知坑"新53：共享进程里 `asyncio.run()` 会改动主线程事件循环状态"）
```
每个 async 用例 → 新建一条工作线程 → 在该线程里 asyncio.run(协程)
```
- 事件循环与"当前循环"都是**线程本地**的，所以主线程的 policy 状态**一次都没被写**；`asyncio.run()` 收尾的 `set_event_loop(None)` 只落在即将销毁的那条线程里。
- 每个用例一条新线程 + 一个新 loop ⇒ 用例之间不存在共享 loop，也不存在"上一个用例把 loop 关掉、下一个拿到 closed loop"。
- **不自夸，挂了计数**：runner 在协程体内取 `asyncio.get_running_loop()` 并给它钉一个自增标记（⛔ 不能用 `id(loop)`：对象销毁后地址会复用 —— 我第一版就用 `id()`，实测 7 个 loop 只数出 4 个，那条闸门当场把真跑通的实现判成不成立，是我的尺子错），跑完打印 `async_awaited / distinct_loops / distinct_threads`。本轮实跑：**7/7，distinct_loops=7，distinct_threads=7**。
- 三者必须与 `collected_async` 全等，否则 runner 直接 rc=1（假绿闸门，不是提示）。

### 顺带说清的取证口径
`asyncio.get_event_loop()` 在 3.13 已经会抛 `RuntimeError`（本机 `test_wo_but_008_ha_exceptions` 三条就是栽在这），3.11 会自建 —— 所以那 16 条 `RuntimeError` 本机≠现网，窗口必须现采（§五）。
