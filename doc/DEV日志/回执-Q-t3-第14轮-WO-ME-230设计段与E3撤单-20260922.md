### C-1 · `/app` 的 md5 对应表（判 R11a／合成件到底装没装机）

命令（NAS 宿主，`$DT` 由《窗口执行单》第 -1 步 export；未 export 先 `echo "$DT"` 非空）：

```bash
date -u
for f in butler/logging_setup.py butler/config.py butler/app.py butler/devices.py; do
  printf '%s\n' "$f"
  md5sum "$DT/$f" | cut -c1-12
  docker exec doubao-butler md5sum "/app/$f" | cut -c1-12
  stat -c 'DT_mtime=%Y' "$DT/$f"
done > workorders/readings/0922/c1_appmd5_$(date -u +%Y%m%dT%H%M%SZ).txt 2>&1; echo "RC=$?"
```

出口判据（**每个文件三格，缺一格＝未采，不记绿**）：

| 格 | 期望出口值 | 读到别的值怎么判 |
|---|---|---|
| 树侧 vs 容器侧 md5 | **同号** | 不等 ⇒ bind 挂载翻面，或可写层里有影子文件（`…/butler ⇒ /app/butler`(rw) 是基线快照 §3.10 实测的）⇒ **停手报 PM** |

### C-2 · `docker inspect` 的 `.Config.Image` ＋ `.Created`

```bash
date -u
docker inspect doubao-butler -f 'ContainerCreated={{.Created}}|StartedAt={{.State.StartedAt}}|Status={{.State.Status}}|Restarts={{.RestartCount}}|ImageName={{.Config.Image}}|ImageID={{.Image}}'

```
> 注意 `.Created` 有两处同名字段：容器 inspect 的 `.Created`＝**容器创建时刻**，镜像的 `.Created`＝**镜像构建时刻** ⇒ 必须两条都跑，只跑一条会得出"镜像没重建"的假结论。

出口判据（对照件＝`workorders/开窗前基线快照-20260921夜.md` §3.3，采集 `epoch=1789994166`）：基线值 = `StartedAt=2026-09-20T20:55:54.610801336Z`、`ImageName=doubao-butler-doubao-butler`、`ImageID=sha256:9121e73d15a1…`、`ImageCreated=2026-09-20T19:08:16.771Z`、`Restarts=0`。

| 读数形状 | 判 |
|---|---|
| `ContainerCreated` 变 **且** `StartedAt` 变 | 发生过 **recreate**（`up -d`）⇒ `.env`／compose／鉴权开关这一类才算生效；同时 `ImageID` 若不变＝旧镜像重建容器 ⇒ **可写层热修会被抹掉**（管家侧基线 4.1 显示可写层无码，风险低，仍要记一笔） |
| 只有 `StartedAt` 变 | **restart** ⇒ 不重读 `.env`，配置类一律记「未生效-需重建」 |
| 两条都不变 | 本窗**没有任何容器级生效动作** ⇒ 凡"要重建才生效"的项全部判「未生效-无重建」，不许用「文件已改」代替 |
| `ImageID` 变 | 镜像被重建（＝本窗明令禁止的 `--build` 面）⇒ 立刻报 PM |
