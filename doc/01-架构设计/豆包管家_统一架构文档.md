## 一、系统定位

**豆包管家**是一个面向家庭全屋智能的 AI 中枢系统：
- 统一接入所有家庭成员的语音/文字输入（小爱/手机/电视/WebUI）
- 统一调度所有设备（HA/米家/电视/电脑）
- 统一记忆所有家庭成员的习惯、偏好、作息
- 主动感知家庭成员状态，提供个性化服务

## 三、核心子系统

### 3.1 对话管理（DialogManager）

**职责**：管理对话状态机，处理多轮对话上下文。

**状态机**：
```
IDLE → LISTENING → THINKING → SPEAKING → IDLE
         ↓          ↓          ↓
      WAITING    ERROR      INTERRUPTED
```

**关键配置**：
- 对话超时：10 秒
- 冷却时间：600 秒
- 去重窗口：7 天

---

### 3.2 记忆系统（Memory-Facts）

**职责**：提取、存储、投喂家庭成员的习惯/偏好/作息。

**工作流**：
1. 对话结束后自动提取事实（LLM）
2. 存入 `memory_facts` 表，状态=pending
3. WebUI 人工审核 → approved / rejected
4. 投喂到对应角色的豆包 APP 长期记忆
5. 检测内容变更 → 标记为 changed → 重新投喂

**角色列表**：
- `butler`：豆包管家（系统级记忆）
- `lidicn`：爸爸（大佬）
- `kevin`：儿子
- `emily`：女儿

---

### 3.3 感知引擎（Perception）

**职责**：融合多源事件，推断用户状态和意图。

**数据源**：
- 人脸识别（TV 端 ArcFace）
- 人体传感器（HA）
- 设备状态变化（开关灯/开空调/开电脑）
- 语音对话历史
- 小爱音箱对话记录

**推断示例**：
- 书房门开→灯亮→电脑开→空调开 → "用户在书房使用电脑"
- 客厅人→厨房人→卫生间人 → "用户从客厅去卫生间"

---

### 3.4 决策引擎（Decision Engine）

**职责**：基于感知结果，决定是否主动说话/推送。

**多层过滤**：
1. **白名单**：只有高置信度事件才触发
2. **夜间规则**：22:00-7:00 不打扰
3. **冷却时间**：同一事件 1 小时内不重复触发
4. **置信度阈值**：≥0.7 才说话，0.5-0.7 只推送
5. **PushGuard**：5 层防护防止推送过载

---

### 3.5 技能引擎（Skill Runner）

**职责**：执行可插拔的自动化技能。

**特性**：
- 熔断器：滑动窗口 + 指数退避 + 日限额
- 可插拔：YAML 定义，热加载
- 冲突检测：避免多条规则互相矛盾

## 四、Koin 轻 Agent 架构

### 4.1 三层路由

| 层级 | 处理方式 | 延迟 | 适用场景 |
|------|----------|------|----------|
| 第一层 | 关键词匹配（0 LLM） | ~100ms | 确定性操作 |
| 第二层 | LLM Function Calling | ~2-5s | 模糊/复杂意图 |
| 第三层 | 自进化沉淀 | - | 优化第一层 |

### 4.2 快速路由规则

**判断标准**：意图确定 → 关键词能唯一映射到一个工具调用。

**示例**：
- "打开书房空调" → `control_device("书房空调", "on")`
- "今天天气" → `get_weather()`
- "谁在家" → `get_presence()`

### 4.3 Source 上下文

区分不同调用端，默认操作不同目标：

| source | 来自哪 | 默认操作目标 |
|--------|--------|--------------|
| webui | 管家 WebUI | 全屋设备 |
| mobile | 手机 APP/PWA | 客厅音箱为主 |
| dp | DeskPilot 电脑端 | 电脑操作优先 |
| tv | TVPilot 电视端 | 电视操作优先 |

## 五、TTS 引擎

**降级链**：
```
NowVoice（首选，拟人化）
  ↓ 失败
EdgeTTS（次选，稳定）
  ↓ 失败
Kokoro（本地，离线）
  ↓ 失败
Bark（兜底，推送通知）
```

**播放通道**：
- 电视打开 → TV 端 TTS Player
- 电视关闭 → 小爱音箱 TTS
- 语音中断 → 停止当前播放

## 六、部署架构

```
Docker 容器（doubao-butler）
  ├── Starlette Web 服务（端口 8095）
  │     ├── WebUI（静态文件）
  │     └── REST API
  ├── MQTT 客户端（paho）
  ├── APScheduler（定时任务）
  └── SQLite 数据库（挂载到宿主机）
```

**数据持久化**：
- 数据库：`/vol1/1000/docker/doubao-butler/data/butler.db`
- TTS 缓存：`/vol1/1000/docker/doubao-butler/tts/`
- 配置：`.env` 文件

## 八、安全设计

### 8.1 认证体系

| 端点类型 | 认证方式 |
|----------|----------|
| WebUI | Session Cookie + 用户名密码 |
| Webhook（豆包） | X-Webhook-Token Header |
| MQTT | Username + Password |
| 内部 API | guard() 中间件检查 Session |

### 8.2 安全防护

- ✅ CORS 限制为实际域名
- ✅ 所有 Webhook 必须带 Token
- ✅ HTML 输出注入 CSP Header（防 XSS）
- ✅ 凭据全部走 .env，无硬编码
- ⏳ 速率限制（待实现）
- ⏳ 登录暴力破解保护（待实现）
