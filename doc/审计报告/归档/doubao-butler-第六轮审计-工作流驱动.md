## 0. 本轮最重要的结论：一条假设被证伪

第五轮 V19 提出"复杂度热点 = 缺陷富集区"，并据此推断 **CC=93 的 `dispatch_tool` 最可能是重灾区**。

**本轮实测：这个推断不成立。**

我读完 `dispatch_tool`（882–1167，286 行）并做了专项核查：

| 检查项 | 结果 |
|---|---|
| 15 个被调函数的同步/异步一致性 | **0 处不一致**（全部 `await` 与定义匹配） |
| 未知工具名处理 | 有兜底 `return f"未知工具: {name}"` |
| 异常边界 | 外层 try/except 捕获，不中断对话 |
| 结构 | 扁平 if-链 + 分组前缀分发（`tv_` / `desk_` / `docker_`） |

**CC=93 是"分发器"这一模式的固有复杂度，不是缺陷密度。** 我此前把"复杂度高"外推成"缺陷多"，在 `on_wakeup`(CC63)、`enqueue_item`(CC32) 上成立，但在纯分发器上不成立——因为分发器的每个分支都是"name == X → 调 Y"的单行映射，没有状态、没有副作用交错。

**修正后的结论**：复杂度与缺陷的相关性成立，但**前提是函数内含状态与副作用交错**；纯查表式分发不适用。这条已写进 `references/patterns.md`。

## 2. V20（P1/P2/P3 分级）：4 处状态文件非原子写

**这是不变量层自动发现的**——4 个文件在前五轮我一个都没读过。

推断路径值得记：项目里已有 4 处正确实现原子写，唯独漏了最该耐久的触发冷却文件（T-2）→ 说明是**遗漏而非无知** → 同类遗漏大概率还有 → 顺着查，果然 4 处。

**但我没有把它们一律定成 P1，而是逐个核实了读取侧的降级行为**——严重度取决于"损坏后读的一方怎么办"，不变量只负责发现：

| 文件 | 等级 | 读取侧行为 | 为什么是这个等级 |
|---|---|---|---|
| `core/fast_routes.py:43` | **P1** | `except Exception: self.routes = []` | **连内置默认都不恢复**，静默置空 |
| `memory/feeder.py:53` | P2 | 只捕 `FileNotFoundError` | `JSONDecodeError` 外抛 → 崩溃但可见 |
| `api/push_routes.py:151` | P2 | `json.load` 在 try 内 | 返回错误，不崩溃 |
| `core/cron_task.py:110` | P3 | JSONL 逐行解析 + 每行单独 try | 只丢截断那一行，最健壮 |

**最后一行是本轮一个诚实的自我修正**：`cron_task` 用 JSONL 且逐行容错，实际风险接近零——如果只按"非原子写"一律判 P1，就是典型的**用模式替代判断**。

## 3. V21（P1）：`fast_routes` 损坏后连内置默认都不恢复

V20 里最严重的一例单独成条，因为它构成完整故障链：

```python
def _load(self):
    if ROUTES_FILE.exists():
        try:
            self.routes = json.load(f)
        except Exception:
            self.routes = []          # ← 损坏：空表，内置也不给
    else:
        self.routes = self._builtin()  # ← 缺失：给内置默认
        self._save()
```

**不对称**：文件缺失有兜底，文件损坏没有。而写入侧非原子（V20 已证），损坏可真实发生。

三连效应：**非原子写（可损坏）→ 损坏后静默置空 → 不恢复内置** = 用户所有快捷指令凭空消失，无日志、无告警、设置页看起来正常。

这与 P0-3（config `logger`）、T-2（冷却归零）**同一病**：状态文件损坏 → 降级路径静默 → 防护/配置消失。**但它是三病里最严重的一例**，因为降级的终点是"功能彻底消失"而非"防护减弱"。

**修复**（约 3 行）：损坏时回退 `self._builtin()` 并留 warning。反测已验证改法可 apply。

## 4. 其他核实结果

### 4.1 `app.py:264` —— 降级为 P3，不是 P1

S3 报"async 内 `subprocess.run`"。核实后：`ffmpeg` 生成唤醒提示音，位于 `lifespan` **启动段**，`timeout=10`，仅首次生成（`if not ding_path.exists()`）。

影响：启动时最多阻塞事件循环 10 秒，**此时尚未开始服务**。且已有 try/except。
**我第五轮把它列为"P1，尚未核实"是过高的**——诚实定为 P3（启动期一次性阻塞，非运行期）。

### 4.2 `registry.py:931` —— 状态码未判（低危）

`get_weather` 里 `data = r.json()` 前未判 `r.status_code`。这是已知的 N-2 模式（deskpilot/tvpilot 同款），此处后果是"天气查询返回乱码而非报错"，影响面极小，列 P3。
