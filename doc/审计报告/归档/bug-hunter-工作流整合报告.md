# bug-hunter：发现 bug 的工作流（整合交付）

> 把前六轮积累的**工具、skill、自写脚本、审计套件**整合成一条可复用流水线
> 位置：`/data/workspace/skills/bug-hunter/`
> 首次端到端运行：**新发现的 V20（4 处状态文件非原子写）证实这条流水线具备自动发现能力**

---

## 1. 为什么是分层，而不是"把所有工具跑一遍"

前面六轮最大的教训不是"缺工具"，而是**每层的能力边界不同，混着用会互相污染结论**：

| 层 | 能做什么 | 不能做什么 |
|---|---|---|
| 模式匹配（S1） | 提高覆盖率：人工 10% → 接近 100% | **不能理解代码**，得先知道 bug 长什么样才能写规则 |
| 属性断言（S3） | **发现没预料到的形状** | 需要人工设计断言 |
| 行为验证（S4） | 实锤 / 证明修法有效 | 不能自动选题 |

**S1 是"我知道要找什么"，S3 是"我不知道，但系统必须恒真"。** 这次整合最重要的判断是：把 S3 单独列为一层，因为它是唯一具备真正发现能力的层。

**实证**：S3 首次运行即命中 4 处非原子写（`push_routes.py:151`、`cron_task.py:110`、`fast_routes.py:43`、`memory/feeder.py:53`）——**这 4 个文件在前五轮审计中我一个都没读过**。V20 由此产生，并已接回审计套件。

## 2. 六阶段

```
S0 环境体检 ──► 工具缺失即降级 + 标红 + exit 2
S1 候选生成 ──► vulture 死代码 / ruff 未定义名 / radon 复杂度 / 自写 AST 反模式
S2 优先级   ──► 复杂度 × 枢纽度 × 历史缺陷密度  →  「下一轮读什么」地图
S3 不变量   ──► 属性证伪（唯一自动发现层）
S4 行为验证 ──► 对接既有 pytest 套件（正测 + 反测）
S5 报告     ──► 汇总 + exit code
```

跑法：`python3 scripts/pipeline.py <repo> [--root butler] [--top 15]`
exit：`0` 全通过 / `1` 行为验证未全绿 / `2` 工具缺失（结论需谨慎）

**实测输出**（doubao-butler）：S1 候选池 128 条、S3 不变量违背 38 条、静默 except 55/724（8%）、优先级地图 195 个文件。

## 3. 三条不可违背的纪律

都来自真实踩过的坑，已写进代码注释。

### ① 工具缺失 ≠ 无问题
沙箱重置过 3 次，每次工具全丢。若那时流水线照常输出"0 缺陷"，等于把缺陷洗白。
→ 必须显式降级 + 顶部标红 + `exit 2`。

### ② ERROR ≠ REFUTED
用例自身失败（依赖缺失 / 桩件失效）不能解读为"缺陷不存在"。曾因缺 `paho-mqtt` 导致真实缺陷被误判为"未复现"。
→ 三态 `FOUND` / `REFUTED` / `ERROR`，ERROR 必须 exit 非 0。

### ③ 反测不许假通过
曾因 `or True` 让反测无条件通过，输出 23 条无意义噪声。**留着假通过的反测比没有反测更危险。**
→ 断言必须精确盯住单个名字/行为。

## 4. 本轮修正的两个检测器缺陷

### 4.1 async 阻塞检测：假阳性 4 → 2
同步 helper 被 `run_in_executor` / `to_thread` 包裹是**合法写法**，原规则误报。
核实 `nowvoice_tts.py:71/75` 确认在 `_gen_and_download`（被 `run_in_executor` 包裹）内 → 排除。
剩下 2 条是真阳性：`docker_tools.py:108`（V18）、`app.py:264`（async lifespan 内 `subprocess.run` 无 executor 包裹）。

### 4.2 原子写检测：漏认 pathlib 形式
原检测器只认 `os.replace`。核实对照组时发现 **`skills/store.py:160`、`triggers/store.py:92` 用的是 `tmp.replace(path)`（pathlib 形式）**，同样是原子写——只认一种写法会把正确实现误判为缺陷。

修正后全仓重扫，结论不变仍是 4 处：**无假阳性、无漏报**。

> 顺便更正我此前的一个表述：说"项目 4 个文件都实现了原子写"是对的，但**实现形式不统一**（2 个 `os.replace`、2 个 `Path.replace`）。这不是 bug，但值得统一。

## 7. 边界（必须说清）

1. **工具提高覆盖率，不提高理解深度**。完整 lifespan、真实 MQTT、SQLite 并发——六轮未解，工具一个都帮不上。
2. **S1/S3 都需要人工复核**。上一轮自写的"return 后不可达"规则产出 1481 条几乎全是误报，已废弃。
3. **工具不会自己归因**。V17 从"未定义名"到"双函数叠写"的定性是人做的。
4. **S3 的价值取决于断言质量**。5 条不变量里 INV-5（副作用守恒）当前 0 命中——不是它没用，是它需要人工标注路径对才能生效。
