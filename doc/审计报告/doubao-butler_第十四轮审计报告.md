## 一、D5 实测：分叉是真的

```
DATA_DIR=/tmp/d5a
  Settings.data_dir = /tmp/d5a          ← 跟随
  ALIAS_FILE        = /app/data/...     ← 不跟随
  ROUTES_FILE       = /app/data/...     ← 不跟随
  self_evolve.DB_PATH = /app/data/...   ← 不跟随
  _SESSIONS_FILE    = /app/data/...     ← 不跟随
```

`Settings.data_dir` 读 `DATA_DIR` 环境变量，但 11 处模块级常量硬编码 `/app/data`。用户按文档把 `DATA_DIR` 指向 NAS 挂载点后，**一部分模块写挂载点、另一部分读写容器内置路径**。

最严重的是 `doubao_webhook.py:60`：它读 `/app/data/role_state.json`，而 `roles/state.py` 和 `memory/feeder.py` 写到 `DATA_DIR` 那份 ⇒ 反向查角色恒为 None ⇒ 回 `unknown_conversation` ⇒ **手机端消息除一个硬编码 CID 外全部被静默丢弃**。

失败方向反直觉：**不崩溃，消息只是不见了。**

**修复**：新增 `butler/core/data_paths.py`，11 处改为统一惰性解析。为什么惰性——模块级常量在 import 期求值，而 `get_settings()` 在 import 期调用有循环导入风险；同时惰性解析保证测试里 `set_settings()` 后能拿到新值。

实测修复后：`ALIAS_FILE` / `ROUTES_FILE` / `DB_PATH` 全部跟随 `DATA_DIR`。

## 二、D10 / D12 实测

**D10 TTS 取令牌**：`_get_token()` 既无 timeout 也无 try/except，而 `synthesize()` 的合成请求显式设了 15 秒超时——**只有一半有防护**。令牌端点挂起只能等 aiohttp 默认 300 秒；且 `await self._get_token()` 写在 `synthesize` 的 try **外面**，异常直接穿到调用方。README 承诺的"TTS 三级降级链不得阻塞对话"在这里没兜住。

已加 10 秒超时 + 异常收敛为显式 `TTSTokenError`（便于调用方区分"令牌拿不到"与"合成失败"）。

**D12 技能渲染**：实测修复后——

| 输入 | 修复前 | 修复后 |
|---|---|---|
| depth 500/1000/2000 | RecursionError | ValueError（明确拒绝） |
| 自引用 dict | RecursionError | ValueError（循环引用） |

深度预算设 24。查了真实技能 JSON，**最大嵌套深度只有 2**，不会误伤合法用法。

## 三、第三次在自己补丁里踩同一个坑

写 D10 补丁时我写了 `raise TTSTokenError(...)`，**却没定义这个类**。

语法完全合法，`patch_lint` 也查不出——它只查"护栏 API 有没有导入"，而这不是护栏 API。后果是：except 分支抛 NameError，**取代了本该表达的"取令牌失败"**，调用方按异常类型分流的逻辑全部失效。

这与审了十四轮的模式**同源**：错误被换成了另一个错误，且不声张。

**新增 W78：检查补丁引用但从未定义的名字（类名/常量）。**

**落地时负向测试先失败了**——我故意删掉 `TTSTokenError` 的定义，patch_lint 仍然输出 OK。原因：主循环里 `if not used_guard_names(tree): continue`，而 `tts_baidu.py` 没有护栏 API 调用，**整个文件被跳过，检查根本没跑**。

这跟上一轮的 W76c（"检查 0 个文件却显示 OK"）是同一处结构缺陷的第二次发作。修法：未定义名检查必须**对所有文件跑**，不能只在含护栏调用的文件上跑（W78b）。

修完再跑负向测试：`tts_baidu.py@['TTSTokenError@47']` 正确报出。还原后恢复 OK。

**另修一处假阳性（W78c）**：`WHITE, GRAY, BLACK = 0, 1, 2` 是元组解包，我的取值辅助只处理 `Name`/`Attribute`，收不到 `Tuple` ⇒ af_scanner.py 三个名字被误报。这与上轮 W77 同源——**辅助函数只处理了"最常见的那一种写法"**。

## 八、本轮最该记住的一条

**负向测试不是可选项——它是唯一能证明检查真的会响的方法。**

W78 写完时，它在我自己造的缺陷上**一声不响**。如果我没做负向测试，就会带着"已经加了未定义名检查"的错觉继续走，而这条检查从头到尾一次都没执行过。

这是本项目第二十二次"静默失效"，也是 W76c（检查 0 个文件显示 OK）之后**同款结构缺陷的第二次发作**。规律很清楚：**当检查挂在"只对命中子集生效"的循环里时，子集外的文件永远不会被看到，而返回值仍然是通过。**

所以任何新增检查都要配一条负向用例，而且要故意把缺陷放在**看起来会被忽略的位置**——本轮放在没有护栏调用的文件里，正好命中盲区。这条经验应该写进规则：新增检查 → 造一个对应缺陷 → 确认报错 → 还原确认恢复。
