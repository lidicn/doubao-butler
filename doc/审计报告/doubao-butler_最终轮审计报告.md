## 三、本轮新增与结案

### D22（新增，high）：`Settings._load_persona` —— D1 的同源第二处

```python
# butler/config.py:357
try:
    raw = json.loads(cfg_path.read_text(encoding="utf-8"))
except Exception:
    return          # ← 无日志
```

与 D1（`config_routes._load_cfg`）读**同一个 config.json**，同样静默 return。
Settings 侧加载失败 ⇒ 人格/成员/规则覆盖整体按默认值运行，**运维无从得知**。

这说明 D1 的修复范围要覆盖**两处读路径**，不能只改 `config_routes`。

### G2 结案：bandit B608 九条全为假阳性

逐条核验 9 条 `Possible SQL injection`：f-string 内插的只有**代码常量拼出的列名/子句片段**
（`', '.join(updates)` 里全是 `status = ?`、`started_at = ?` 字面量），
用户值一律走 `?` 占位符 ⇒ 无注入。

**但要给开发者留一句**：这个写法**脆弱**——若日后有人把用户可控的列名加进
`updates`/`sets`/`conditions`，会立刻变成真注入且无任何护栏。建议加列名白名单断言。

### W91：失败开放 PoC 的适配器是按项目硬编码的

实测 doubao-butler：FO-01 静态命中 2 条，都不在 `ADAPTERS` 里 ⇒
`want` 回退到 `list(ADAPTERS)` ⇒ **跑的是 AutoForge 的两个探针** ⇒
`ModuleNotFoundError: No module named 'autoforge'` ⇒ 输出 `{"unavailable": 2}`。

危险在于输出**看起来完全正常**：targets=2、unavailable=2，
与"本项目真的没有可测目标"在报表上无法区分。
第十九轮我把它记为"归因不明"，实际原因一直写在 `detail` 里（`reason` 字段为空）。

已修：无匹配适配器时显式输出 `no_adapter`，不再回退跑别的项目探针。

### W90b：归因必须多字段取

不同 PoC 把原因放不同字段（`poc_state` → `reason`，`poc_failopen` → `detail`）。
首版只读 `reason` ⇒ 错过了一个"探针在跑别的项目"的真问题。

D17 补丁副本实测：

```
拦截  http://127.0.0.1:8123/api      不允许访问内网地址
拦截  http://localhost:8123/api      不允许访问本机地址
拦截  http://homeassistant.local     不允许访问内网域名
拦截  http://[::1]:8123/api          不允许访问内网地址
```

**需要你定夺的取舍**：`api.example.com` 在沙箱无 DNS 时也被拦（fail-closed：
"解析不了就无法证明它不是内网"）。外部 API 在 DNS 临时故障时注册会被拒。
注册是一次性操作可重试，但要你确认这个方向。

## 七、二十轮复盘：唯一有效的那条纪律

累计二十余次**工具 / 探针 / 样本 / 环境静默失效**，失效源位置一路外移：

```
我们写的分析器 → 补丁 → 外部工具 → 环境 → 探针自身 → 共享样本 → 调用方式
```

第二十轮的三项（W89 扫描范围、W91 适配器回退、W90b 归因字段）都在后半段。

**共同点无一例外：表现为"命中变多/变少"或"看起来正常运行"，而不是报错。**

唯一有效的对策仍是那一条：

> **任何"看起来修好了"或"看起来在测"，都先怀疑工具与环境，再相信结论。**

本轮最直接的兑现是 W89——100 个一次性审计脚本一直被当成产品代码扫描，
RSC-03 贡献 95 条假噪声。**排除后数字变小了，但审计质量变高了。**
排除不是为了让数字好看，是为了让数字**可信**。
