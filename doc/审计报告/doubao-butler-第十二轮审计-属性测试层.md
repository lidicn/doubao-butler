## 3. 两条经核实的负面结论

### 3.1 静默窗口实现是正确的（排除了高风险假设）

跨午夜时区判断是最容易 off-by-one 的地方。四条属性全过：

- **可播区间长度精确匹配**：`start<end` 得 `end-start` 分钟；`start>end` 得 `(1440-start)+end`；`start==end` 得 1440。400 组随机组合无一例外
- **左边界可播**：`quiet_start` 那一刻不会被判静默
- **白天绝不静默**：默认 06:50–23:00 下，08:00–22:00 全量程可播
- **全量程返回 bool**：0–1439 无异常

**结论**：`is_quiet` 没有 off-by-one。此前 V14 记录的"双静默机制"是**配置层问题**（队列常量 vs WebUI 可改的 `dnd_windows` 两套并存），不是这段判断逻辑的 bug。两件事要分开。

### 3.2 环境变量解析的回退语义是健壮的

300 组垃圾字符串（`"1e"`, `"--"`, `"++"`, `""`, `"  "` …）喂给 `_env_int` / `_env_float`：

- **从不抛异常**
- **解析失败一律原样返回 default**

这是"配置损坏 → 应用起不来"的第一道防线。它守住了——所以 P0-3（config `logger`）是**单点缺陷**，不是系统性回退缺失。

**注意**：`_env_float("2E308")` 返回 `inf`。这是 Python `float()` 的正常行为，不是缺陷——**是我第一版断言写错了**（`abs(inf-inf)=nan`，`nan<1e-9` 判 False），已修正。

### 3.3 已知缺陷 V3 被属性化（刻意为红）

`inv_real_rooms_all_resolvable` **保留红色是刻意的**——它是 V3（房间映射覆盖不全）的常驻回归断言。hypothesis 独立找到的最小反例是**卫生间**，与第三轮人工核查一致。

**修好 V3 后这条应转绿。** 这提供了一个此前没有的东西：**修复的可验证判据**。

## 5. 修掉的三个工具自身缺陷

本轮踩了三次同一个坑，值得单独记：

**`__main__` 块位置问题（踩三次）**——每次用 `cat >>` 追加新属性后，`if __name__ == "__main__"` 就不在文件末尾了，导致**新用例静默不执行，报告仍显示"全部通过"**。这比报错危险得多。

第三次后彻底改掉：**删除 `__main__` 块，改为 `main()` 函数由 pipeline 调用**。从机制上消除该坑。

另两个：
- 属性测试脚本的 `inv_` 收集用 `globals()`，必须在调用时求值（已保证）
- `abs(inf-inf)=nan` 导致 inf 比较失败（断言 bug，非产品 bug）

**教训**：工具自身的"静默失败"是审计工具最危险的失效模式——它让"全部通过"变成一个谎言。

## 7. 诚实边界

1. **crosshair（符号执行）与 mutmut（变异测试）装上了但本轮未使用**。前者能自动找边界反例（比 hypothesis 更聪明），后者能验证"现有测试是否真的能抓住缺陷"——**mutmut 对本项目尤其有价值**：624 个测试中若有一批是"永远通过"的空测试，变异测试能直接暴露。
2. **属性测试未覆盖高风险区**：状态机、TTS 队列过载/熔断、SQLite 并发。
3. **十一轮零进展的仍是运行时验证**：完整 lifespan、真实 MQTT、SQLite 并发。
