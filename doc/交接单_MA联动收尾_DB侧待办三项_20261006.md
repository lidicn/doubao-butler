## 一、service_token 切换（DCD Q5 + 路线图 3.3.4）

### 背景

MA 已按 DCD 20261001/20261005 裁定完成 token 体系合并：
- 新增 `service_tokens.py`（`svc_` 前缀、sha256 落盘、常量时间比对）
- `app.py` 增加服务令牌校验分支与作用域门
- 30 天双轨期：旧 `BUTLER_TOKEN`（env 导入）仍可用，新 `svc_` 令牌并行
- 旧令牌使用量监控端点：`GET /api/config/service-tokens/legacy-usage`（需认证）
- 下线条件：旧令牌连续 7 天使用量为 0 可吊销

### DB 侧需做

1. **申请新 service_token**：联系 MA 侧签发 butler 实例专属令牌（一实例一令牌，DCD Q3=A）
2. **切换 butler 出站调用**：将所有调用 MA API 的地方从 `BUTLER_TOKEN` 改为新 `svc_` 令牌
3. **验证**：切换后调用 MA API 应正常返回 200
4. **观察期**：切换后观察 7 天，确认旧令牌使用量降为 0
5. **通知 MA 下线旧令牌**：确认旧令牌 7 天零使用后，通知 MA 吊销 `butler-env` 记录

### 注意

- 旧 `BUTLER_TOKEN` 是 env 导入的只读记录，不落盘、不可在 MA 侧吊销（只能等 30 天双轨到期或 env 移除）
- 新令牌带 `token_kind` 字段，MA 日志会区分 `service` / `legacy`，便于监控切换进度
- 双轨到期日由 SP 定，代码不写死
