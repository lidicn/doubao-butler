## 问题（大白话）

最终轮审的 D17 是「护栏只做一半」：HA 转发地址可填内网/本机/`.local`，等于让管家替攻击者访问自家内网。补丁副本已把四类形态全拦住（127.0.0.1／localhost／homeassistant.local／[::1]，实测 5/5 全拦截），**但护栏的判据是「解析不了就无法证明它不是内网」**——外部域名在 DNS 临时故障时也会被拒。

要定的只有一件事：**注册外部 API 那一刻如果 DNS 恰好解析不了，宁可拒绝（用户重试一次），还是宁可放行（放过一个证明不了的地址）？**

## 选项

- **A. 维持 fail-closed（推荐 ⭐⭐⭐⭐⭐）**：被拒的代价＝重试一次（注册是一次性、可重试操作）；放行的对价＝DNS 重绑定窗口（先答公网、再答内网）被打洞。风险几星：A ≈ 1 星（用户侧偶发重试）。
- B. 解析失败放行（⭐）：把上面对价反过来付，风险 ≈ 3 星。
- C. 失败时走人工白名单（⭐⭐）：多一张要人维护的表，收益只有 B 的一半，且白名单本身是新的攻击面。

## 我这边（裁定前）

D17 的**内网拦截主体**不依赖这个取舍；本件只钉「解析失败」那一格方向。裁定后我按结果落码＋补判据测试，验收证件＝四类内网形态各拦一行＋外部域名按所选方向那一行，实跑输出贴回执。
