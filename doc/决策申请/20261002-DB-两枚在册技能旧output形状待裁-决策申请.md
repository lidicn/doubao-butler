# 决策申请 · DB：两枚在册技能的 output 是"旧形状"，严格化会让它们整只消失（要裁：迁移数据 vs 加映射层 vs 任其消失）

> 　　　判例同文书 `:110`：「说了不做」比「没做」更坏……处置可以是"接上"也可以是"拆掉"，唯独不能"留着"

## 一、大白话讲这是什么

裁定④ 让我把「名单里没有的输出类型」从**悄悄丢掉**改成**当场报错**。这一条我已经落了码（提交 `8c9f631`）。

落码前我先量了一遍半径，发现盘上有**两枚主人自己建、现在还在启用中**的技能，它们的 `output` 段整块是**旧形状**（一个对象，不是列表）。旧形状不是"多写了一个非法类型"，而是**整段读不懂**：

- 读不懂 ⇒ 归一层把它当成"没有输出" ⇒ 落回默认输出「电视弹窗＋开口念」；
- 主人写的其实是「推送到手机、**不要开口**」和「推送到手机＋**用告警音**」；
- 所以今天的效果是：**该闭嘴的在开口，该发手机告警的一条都没发出去**。这正是裁定④ 点名要治的那个洞（「全跳光则回落成 tv_notify，本该不动声色的技能会开口」）。

但如果我把"旧形状"也纳入"当场报错"，`store.load()` 的跳过分支会**当场把这两枚技能整只丢掉**——下次重启起，主人的面板上少两个技能，且只在日志里留一行 warning。

⇒ **两边都碰**：不严格化＝继续违反裁定④ 的判例；严格化＝单方面让主人的两枚技能消失。**这一刀不该由开发位自己落**。

## 二、我量到了什么（全是现读，⛔ 推测）

尺子＝`scripts/audit_1002/census_output_types_1002.py`（按 JSON 结构取，⛔ grep：`"type"` 在 brain／senses 里同名不同物）

| 要什么 | 读数 |
|---|---|
| `store.load()` 真会加载的技能文件数 | `LOADED_FILES=24`（三档目录 `builtin`／`user`／`agent`；其余 7 个目录不加载，脚本另列） |
| output 形状不是列表的文件 | `SHAPE_NON_LIST=2`，逐枚点名见下 |
| 这两枚是否启用 | 两枚都 `status=enabled`、`source=user`、`version=1` |
| 白名单外的**类型**（裁定④ 已治那半） | `UNKNOWN_OUTPUT_ITEMS=0` ⇒ 与裁定文里「在架 22 条 output 全在白名单内」同号（我这把尺 `SUM\|kinds=3\|total_output_items=22\|unparseable=0`） |
| 归一后的实际输出 | `validate_skill` 返回 `err=''`（＝不报错），两枚都归一成 `[{"type": "tv_notify", "tts": true}]` |

两枚的原文意图（现读，逐字）：

1. `data/skills/user/anti_addiction_alert.json`（防沉迷警告）
   `output = {"role":"小爱","devices":["xiao_study","xiao_living_room"],"bark":true,"bark_title":"防沉迷提醒","bark_level":"critical","bark_sound":"alarm","tts":true}`
   ⇒ 手机侧是 **critical＋告警音**的防沉迷告警；现在这些全部丢失，只剩一条电视播报。
2. `data/skills/user/device_inspection.json`（小爱设备巡检）
   `output = {"role":"小爱","devices":["xiao_study"],"bark":true,"bark_title":"设备巡检报告","bark_level":"active","bark_group":"inspection","tts":false}`
   ⇒ 主人明确写了 **`tts: false`**；现在得到的是电视弹窗＋开口念。

同族另一把尺（顺手量的，⛔ 当成受害者）：`TRIG_SHAPE_VICTIMS=2` 是同样这两枚，但它们旧的复数字段 `triggers` 值是**空列表 `[]`** ⇒ **触发侧零意图丢失**，本件⛔ 把这条计入半径。

跳过分支的方向（现读 `butler/skills/store.py:55-58`）：`normalized, err = validate_skill(raw)` → `if err:` → `logger.warning(...)` → **`continue`**＝整只文件不进索引。

我⛔ 量的（诚实留空）：bark 通道在手机侧**此刻是否真能发出去**（`notify/router.py` 里有 `CHANNEL_BARK` 与 `if self.bark is not None:` 分支，但生产装配时 bark 端口是否为 None 未量）＝**未量**。这条只影响"选项 A/B 的收益有多大"，不影响本件要不要裁。

## 三、四条选项

| 选项 | 做法 | 好处 | 代价／风险 | 推荐 |
|---|---|---|---|---|
| **B** | **迁数据**：把这 2 个 json 的 `output` 重写成现行列表形状（先 `dry-run` 打印改前改后两版给我比对，改前做快照），代码侧只补一条"旧形状＝报错"的闸 | 主人写的意图真落地（该闭嘴的闭嘴、该发手机的发手机）；归一层⛔ 为 2 枚老数据长出第二种形状＝守住裁定④「一条路，不留两套」 | 要授权动**主人自己的数据文件**（开发位不代改）；映射若写错＝播报内容变形，故必须逐枚比对＋可回滚快照 | ★★★★ |
| A | 加映射层：`schema` 里认这种旧形状，把 dict 翻成 `[bark(...), tv_notify(tts=…)]` | 不动主人数据，行为同样纠正 | 归一层从此**长期存在两套 output 语法**，与裁定④「一条路，不留两套」正面冲突；以后每个读 output 的地方都要考虑两种形状 | ★★ |
| C | 严格化：旧形状＝当场报错，⛔ 迁数据 | 违反"沉默"这条最彻底，代码最干净 | 下次 restart 起**两枚在册技能从面板消失**，只剩一行 warning；主人会发现功能不见了 | ★ |
| D | 保持现状（本笔已落的代码就是现状） | 零风险、零变动 | 「该闭嘴的继续开口、该发手机的继续不发」＝裁定④ 判例「唯独不能留着」的直接违例 | ☆ |

**开发位推荐 B**，并且顺序要钉死：**先迁数据（B 的第一半）→ 盘上确认两枚已是列表形状 → 再落"旧形状＝报错"那条闸（B 的第二半）**。反过来＝中间那一刻两枚技能同时不在索引里。

## 四、我这侧已经做的／刻意不做的

- 已做（`8c9f631`）：名单外**类型**当场报错；生成端模板不再往 `ha_service` 灌；`sandbox`／`conflict` 两扇安全门改按 `brain.engine` 判（原本按 output 里的 `ha_service` 判＝schema 永不放行那个词＝两道门恒空）。

- 本件⛔ 排进任何部署窗：两枚技能的纠正与"一次 restart"是两件事，裁定与数据迁移都没落之前，重启只会维持现状（D）。
