## 一、结论一句话

**两本账记的不是同一件事，但裁定的"评估 vs 执行"这个说法要修正一格：`trigger_audit` 记的不是"触发链被评估了多少次"，而是"每条定时腿跑了一轮没有"（心跳）。**
"触发规则被评估了多少次"这件事**今天没有任何一本账在记**——它是一个缺口，不是一个口径。

## 四、这次比对查出来的六件事

1. **`trigger_audit` 是心跳账，不是评估账。** wrapper 每轮记一行，`matched_rule`/`event_type` 在 `mark_success/mark_error` 这条路上**根本不传**（`audit.py:65` 的默认值是空串），所以这本账回答的问题是"**这条定时腿活着吗、多久跑一次、这一轮有没有抛异常**"，回答不了"命中了哪条规则"。
2. **表结构里有三列是死的**：`actions_count` / `success_count` / `fail_count` 全表恒为 0（`registry.py:155/175` 调用时不传，DDL 默认 0）。裁定 §A 说"trigger_runs 是真执行结果"这个信息层，**在 audit 这本账里并没有镜像**——它连"这轮跑了几条动作"都没记。这不是冗余，是**字段先建、写入方后来忘了喂**。
3. **`trigger_audit` 里混进了第四个种群**：MCP 工具调用（`source_type='mcp'`，实测 35 行，`source_id="mcp:<tool_name>"`）。它和定时心跳同表不同义 ⇒ 任何"trigger_audit 行数＝触发次数"的算法都会把 MCP 调用一起算进去。
4. **`TriggerAuditor` 的路径是硬编码 `/app/data/push_guard.db`**（`audit.py:47` 默认参数），**不读 `settings.data_dir`**。现在容器里两者重合所以看不出问题；一旦 `DATA_DIR` 改指向，`trigger_audit` 会**静默留在老路径**，而新路径里长出另一个空表——这类"账本分家"最难查。⚠ 属于"改存储路径"红线，**本窗不动，只登记**。
5. **审计的查询接口自带假绿通道**：`audit.py` 的 `query()`/`get_stats()` 在**读失败时返回 `[]` / `{"total": 0...}`**（`:133`、`:168`）。按纪律 4，一个 0 在被证明尺子能咬之前不算读数——所以这次新加的新鲜度读数**没有沿用它们的形状**：`latest_ts()`（`audit.py:91`）读失败**直接抛**，由 `/api/status` 那一格记成 `read_error`，⛔ 折成 0。
6. **`trigger_runs` 的 `status='error'` 里混着"设计上该跳过的"**：全表 43 条 error 中 **19 条**是 `errors=['skill quarantined: ']`（`decision_heartbeat` 25 条里 21 条 error）。这是格3② 的隔离态人工终态——**按设计不该算失败**，但它落在同一列里。所以"这周触发失败几次"用 `trigger_runs` 算之前，必须先排除 `skill quarantined` 这类终态跳过行（见 §六）。顺带记一条小缺陷：隔离消息里 **skill 名是空的**（`skills/runner.py:146` 打的是 `f"skill quarantined: {reason}"`，`reason` 为空串时读起来就成了"quarantined: "），要判"哪个技能被隔离"只能回查库。

## 五、正名（裁定 §A 的"正名不合并"落成这四句话）

- `trigger_runs` = **执行流水**：一次 trigger 命中、动作跑完（或报错）才写一行，带动作清单。**"触发了多少次/成功多少次"只认这本。**
- `trigger_audit` = **调度心跳**：每个被 `wrap_scheduler_job` 包起来的定时源每轮一行。**"这条定时腿活着吗/最近一次多久以前"认这本。**
- `push_audit`（同库第三本）= **推送风控流水**：每次 Bark/推送决策一行。
- **"触发链评估了多少次"目前没有账**。要它就得新记（engine 入口计数），⛔ 拿心跳账冒充——冒充的结果是"评估次数"永远等于定时轮数，跟真实事件量无关。

## 六、统计口径（钉进路线图 §14.5，改口径要走 DCD）

| 要回答的问题 | 用哪本 | 怎么算 | 坑 |
|-------------|--------|--------|-----|
| 这周真触发了多少次 | `butler.db.trigger_runs` | `COUNT(*) WHERE ts>=周起` | ⛔ 用 audit（那是心跳，147 倍） |
| 这周触发失败多少次 | `trigger_runs` | `status='error'` **再排除** `error LIKE '%skill quarantined%'` | 隔离态是设计跳过，不是失败 |
| 某条定时腿活着吗 | `push_guard.db.trigger_audit` | 该 `source_id` 的 `MAX(ts)` 离今时长，对照它登记的 `expected_interval_sec` | ⛔ 把行数当触发数 |
| MCP 被调了多少次 | `trigger_audit` | `WHERE source_type='mcp'` | 同表混种，必须带这个 WHERE |
| 触发链评估了多少次 | **无账可答** | 待建（engine 入口计数） | 用心跳冒充＝假读数 |

## 七、health 面这一腿怎么落的（本窗已改码）

`/api/status`（鉴权后）新增 `ledgers` 块，由 `butler/store/ledger_freshness.py` 组装：

```
"ledgers": {
  "statistic_key": "统计口径：触发次数用 trigger_runs；定时腿心跳用 trigger_audit",
  "trigger_runs":  {"db": "butler.db", "last_ts": …, "last_age_s": …, "rows_24h": …, "meaning": "真执行…"},
  "trigger_audit": {"db": "push_guard.db", "last_ts": …, "last_age_s": …, "meaning": "调度心跳…"}
}
```

三格形状各不同，且**互不覆盖**：
- 读到但表空 → `last_ts=0.0`、`last_age_s=null`；
- **读不到 → `read_error`，且 `last_ts` 这个键根本不出现**（`tests/test_ledger_freshness.py` 里 `test_read_failure_becomes_read_error_not_zero` 钉的就是这条）；
- auditor 没初始化 → `unavailable`（⛔ 用 0 假装有账本）。

接线点：`butler/api/system_routes.py` 的 `status()`（`"ledgers": ledger_freshness.snapshot(rt)`）。
新增读数函数：`butler/store/repo.py:200 latest_trigger_run_ts()`、`:211 count_trigger_runs_since()`、`butler/triggers/audit.py:91 latest_ts()`。

⚠ `/api/health` 按 NAS 规范**必须恒 200**（`system_routes.py:11` 只做 `{online: true}`），所以新鲜度读数落在 `/api/status`；容器健康检查看不到这一格 ⇒ **现网自动告警仍缺一条腿**，登记为 §14.5 的后续项（要接 Bark 得另开：动发声/告警面属红线）。

**运行时腿：未生效。** 本窗只把码合进权威树，没动容器（`up -d` 属现网动作，且第 4 腿写面闸在停摆未结案时会拦）。部署窗口内要现采一次 `/api/status` 的 `ledgers` 块。

## 八、这次顺手修掉的一个测试污染（与双账本无关，但它是"读数造假"的源头之一）

`tests/test_decision_engine.py:93-94` 把 `butler.store.db.get_settings` 和 `repo.get_settings` **改成指向一个 TemporaryDirectory 且不回收**；上下文退出后目录已被删除，此后**同进程内每一个碰库的用例都读到那个不存在的库**，以为自己读的是临时库。
本窗新加的 `test_ledger_freshness.py` 在 setUp 里钉了一条自证腿（`PRAGMA database_list` 的文件列必须等于本次临时库），第一次整档跑就把肇事路径打了出来：`want=/tmp/butler_ledger_…/butler.db got=/tmp/butler_decision_test_…/butler.db`。
修法用 `self.addCleanup(setattr, …)` 两行回收，⛔ 给整个方法体重缩进。
