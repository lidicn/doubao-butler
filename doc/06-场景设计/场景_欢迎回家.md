# 欢迎回家智能场景方案

> 创建：2026-09-18
> 状态：规划中，待基建稳定后实施

## 现状

- 现有 NR flow：门磁 `binary_sensor.e4aaec82dcd7_contact` → on → 机械播报"欢迎回家"
- 问题：无身份识别、无上下文、机械感强、深夜也播

## 设计目标

不是机械欢迎，而是根据谁回来了、什么时间、家里什么情况，由不同角色用各自音色自然对话。

## 三段式链路

### Phase 1：开门瞬间（玄关，1-2 秒）

- **触发**：门磁 on
- **身份识别**：手机 BLE（lidicn 手机 / Kevin iPad），比人脸识别快且可靠
- **角色**：贾维斯（书房方向）或默认管家
- **动作**：一句话简短欢迎，"老板回来了" / "欢迎回家"
- **约束**：
  - 30 分钟冷却（同一人不重复播）
  - 22:00-07:00 简化版（不说话，只开客厅灯）
  - WebUI 可开关

### Phase 2：走到客厅（客厅人体感应，30 秒内）

- **触发**：客厅 mmwave/PIR 检测到人（开门后 30 秒窗口内）
- **角色**：豆包管家（客厅小爱）
- **LLM 生成汇报**：
  - 天气（下雨？温度？）
  - 家里设备状态（空调/灯谁开着）
  - 家人动态（谁已经在家）
  - 今日日程/明日提醒
- **动作链**：自动开客厅灯 + 空调调舒适温度

### Phase 3：安防简报（可选，晚间/长时间外出后）

- **触发**：MA 巡检数据 + 回家事件
- **角色**：顾安恒
- **内容**："你离开期间一切正常" / "厨房烟感有一次误报已恢复"
- **约束**：仅在晚上 18:00 后或外出超过 4 小时才触发

## 前置依赖（待修复）

1. **书房触屏 TTS 循环播放 bug** — X08A 需云端 pause，当前未完全解决
2. **NowVoice 稳定性** — 当前 token/音色偶发问题
3. **角色-音箱绑定** — 需确认每个 output_devices 的 ha_entity 正确
4. **BLE 身份识别** — 手机蓝牙状态进 HA（需 BLE tracker）
5. **客厅人体感应** — mmwave 传感器事件进 trigger 引擎

## 不做的事

- 不做人脸识别常开（隐私 + 硬件不支持）
- 不做全屋逐房间接力（基建不稳前先单点）
- 不用 TTS 固定模板（用 LLM 生成每次不同的欢迎语）
