# 豆包管家 (doubao-butler) — 项目设计文档

> 版本：v1.0
> 日期：2026-09-02
> 状态：待确认
> 定位：拟人化家庭 AI 管家，基于人脸识别 + 多模态场景理解 + 记忆系统，实现主动对话与个性化交互

---

## 1. 项目定位

### 1.1 是什么

豆包管家是一个运行在 NAS Docker 上的拟人化家庭 AI 管家服务。它：
- 通过 TV 端人脸识别知道"谁在客厅"
- 通过 memory-agent VLM 多模态知道"客厅发生了什么"
- 通过记忆系统知道"用户喜欢什么、讨厌什么、之前聊过什么"
- 通过 TTS 语音在电视上主动打招呼、提醒、聊天
- 支持小爱音箱语音触发、人体传感器主动唤醒

### 1.2 不是什么

- 不是通用聊天机器人（不回答百科问题，只做家庭场景交互）
- 不是 memory-agent 的一部分（独立部署，隐私隔离）
- 不是 Node-RED 流程（复杂对话状态管理不适合 Node-RED）

### 1.3 核心价值

| 价值 | 说明 |
|------|------|
| **拟人化** | 有名字、有性格、有记忆，不像机器 |
| **主动式** | 不是等用户问，而是主动打招呼、提醒、关心 |
| **场景感知** | 知道当前客厅情况，对话有上下文 |
| **个性化** | 对不同家庭成员有不同的称呼、话题、语气 |
| **不重复** | 记忆系统防止每天说同样的话 |

## 3. 核心模块设计

### 3.1 唤醒引擎 (WakeupEngine)

#### 3.1.1 唤醒方式

| 唤醒方式 | 触发条件 | 优先级 | 说明 |
|---------|---------|--------|------|
| **人脸识别** | TV 端识别到新的人进入客厅 | 高 | 立即打招呼 |
| **人体传感器** | 客厅人体传感器检测到有人，且 30 秒内无对话 | 中 | 主动关心 |
| **定时唤醒** | 特定时间点（早上 8 点、晚上 10 点） | 中 | 播报日程/提醒 |
| **小爱音箱** | 用户说"小爱同学，叫豆包管家" | 高 | 启动对话模式 |
| **场景触发** | memory-agent 检测到特定场景（如客厅很乱） | 低 | 委婉提醒 |

#### 3.1.2 唤醒策略

- **冷却机制**：两次主动对话间隔至少 10 分钟（防止打扰）
- **场景判断**：
  - 电视在播放视频 → 不主动说话（只在用户暂停时）
  - 深夜（23:00-07:00）→ 不主动说话
  - 多人在客厅 → 简短问候，不展开对话
- **用户偏好**：用户可以设置"免打扰时段"、"主动对话频率"

### 3.2 对话管理器 (DialogManager)

#### 3.2.1 对话状态

```
IDLE（空闲）
  │
  ├─ 唤醒事件 → LISTENING（监听中，等待用户说话）
  │                │
  │                ├─ 用户说话 → THINKING（思考中，生成回复）
  │                │                │
  │                │                └─ 回复生成 → SPEAKING（说话中）
  │                │                                  │
  │                │                                  └─ 说完 → WAITING（等待回应，5秒）
  │                │                                                    │
  │                │                                                    ├─ 用户回应 → THINKING
  │                │                                                    └─ 无回应 → IDLE
  │                │
  │                └─ 超时（10秒无说话）→ IDLE
  │
  └─ 主动对话触发 → SPEAKING（直接说话，说完后进入 WAITING）
```

#### 3.2.2 上下文管理

- **短期上下文**：当前对话的最近 10 轮（内存）
- **中期上下文**：今天的对话摘要（SQLite）
- **长期记忆**：用户偏好、重要事件、习惯（ChromaDB 向量）
- **场景上下文**：当前客厅情况（从 memory-agent 获取）

#### 3.2.3 人格设定

```
你是"小豆"，一个亲切、幽默、有点唠叨的家庭 AI 管家。
- 对 lidicn 称呼"豪哥"，语气像老朋友，可以开玩笑
- 对 Kevin 称呼"小凯"，语气像大哥哥，关心学习和健康
- 对小女孩称呼"小公主"，语气温柔，鼓励为主
- 不要太正式，用口语化表达
- 不要重复说同样的话（记忆系统会记录）
- 不要主动聊沉重话题（工作压力、健康问题等），除非用户提起
- 提醒要委婉，不要说教
```

### 3.3 记忆系统 (MemorySystem)

#### 3.3.1 记忆类型

| 类型 | 存储 | 用途 | 保留期 |
|------|------|------|--------|
| **对话历史** | SQLite | 上下文、防重复 | 30 天 |
| **用户偏好** | SQLite + ChromaDB | 个性化回复 | 永久 |
| **场景记忆** | SQLite | 什么场景说过什么话 | 7 天 |
| **重要事件** | ChromaDB | 生日、纪念日、重要约定 | 永久 |
| **防重复哈希** | SQLite | 防止 7 天内说同样的话 | 7 天 |

#### 3.3.2 防重复机制

每次生成回复前：
1. 计算回复内容的语义哈希（embedding）
2. 在 ChromaDB 中搜索最近 7 天的相似回复
3. 如果相似度 > 0.85 → 重新生成（换个说法或换个话题）
4. 最多重试 3 次，仍重复则跳过本次主动对话

#### 3.3.3 用户偏好学习

- 显式学习：用户说"我不喜欢..."、"我喜欢..." → 直接记录
- 隐式学习：用户对某话题回应积极 → 增加该话题权重；回应消极 → 减少
- 定期整理：每周生成用户偏好摘要，供对话生成使用

### 3.4 TTS 语音模块

#### 3.4.1 语音生成

- **方案 A（推荐）**：edge-tts（微软免费 TTS，音质好，支持中文多种音色）
- **方案 B**：豆包 TTS API（需付费，音质更好，支持情感）
- **方案 C**：本地 Piper TTS（离线，音质一般）

#### 3.4.2 播放方式

| 播放设备 | 方式 | 延迟 | 适用场景 |
|---------|------|------|---------|
| **电视扬声器** | TV 端 APK 接收音频流，AudioTrack 播放 | 低（<1s） | 客厅主动对话 |
| **小爱音箱** | TTS 文本 → 小爱 TTS API → 小爱播放 | 中（2-3s） | 全屋广播 |
| **手机推送** | Bark 推送文字 + 语音链接 | 高 | 重要提醒（用户不在家） |

#### 3.4.3 TV 端播放协议

doubao-butler 生成 MP3 音频文件后：
1. 上传到 NAS 静态文件服务（或 TV 端可访问的 HTTP 地址）
2. 调用 TV 端 API：`POST http://192.168.2.238:8080/api/tts/play`
   ```json
   {"url": "http://192.168.2.200:8090/tts/xxx.mp3", "volume": 80}
   ```
3. TV 端 APK 用 MediaPlayer 播放

**TV 端需要新增**：`/api/tts/play` 端点，接收音频 URL 并播放。

## 4. 外部 API 集成

### 4.1 TV 端人脸识别

```
GET http://192.168.2.238:8080/api/scan/latest
Response:
{
  "faces": 1,
  "persons": [
    {"name": "Kevin", "similarity": 0.923, "age": 13, "gender": 0, "state": "stable"}
  ],
  "fused": [...]
}
```

**使用场景**：
- 唤醒时：知道谁在客厅，用对应称呼打招呼
- 对话中：知道谁在说话，个性化回复
- 离开时：知道人走了，结束对话

### 4.2 memory-agent VLM 场景分析

```
POST http://192.168.2.200:8086/api/vision/analyze
Body: {"room": "客厅", "force": true, "wait": true}
Response:
{
  "ok": true,
  "persons": [
    {"identity": "Kevin", "action": "坐在沙发上玩手机", "posture": "坐", "confidence": 0.9}
  ],
  "scene": "客厅，一人坐在沙发上玩手机",
  "snapshot_quality": "good"
}
```

**使用场景**：
- 主动对话前：获取当前场景，让对话有上下文
- 提醒触发：检测到特定场景（客厅很乱、有人久坐不动）
- 对话中：用户问"我在干嘛"时回答

### 4.3 memory-agent 行为记录

```
GET http://192.168.2.200:8086/api/behaviors?room=客厅&limit=10
Response:
{
  "count": 10,
  "events": [
    {"ts": 1725264000, "room": "客厅", "persons": [...], "scene": "...", ...}
  ]
}
```

**使用场景**：
- 记忆系统：读取历史行为，了解用户习惯
- 对话中："你今天看了 3 小时电视，注意休息"
- 统计：用户活动规律

### 4.4 Home Assistant 传感器

```
GET http://192.168.2.200:8123/api/states/binary_sensor.living_room_motion
Headers: Authorization: Bearer <ha_token>
```

**使用场景**：
- 唤醒引擎：人体传感器触发主动对话
- 场景判断：电视是否在播放、灯是否开着
- 设备控制：对话中控制设备（"帮我关灯"）

### 4.5 doubao2api LLM

```
POST http://192.168.2.200:9090/v1/chat/completions
Body:
{
  "model": "doubao",
  "messages": [
    {"role": "system", "content": "<人格设定 + 上下文 + 记忆>"},
    {"role": "user", "content": "<用户说话或主动对话触发>"}
  ],
  "temperature": 0.7,
  "max_tokens": 200
}
```

## 5. 典型场景示例

### 5.1 场景一：Kevin 放学回家

```
触发：TV 人脸识别到 Kevin（新进入客厅）
唤醒引擎：检测到新人，立即打招呼
对话管理器：
  上下文：Kevin，13岁，男生，下午 17:30
  记忆：Kevin 今天还没说过话；昨天提醒过写作业
  生成回复："小凯回来啦，今天学校怎么样？作业多不多？"
TTS：生成语音，电视播放
等待回应：
  Kevin："还行，作业不多"
  生成回复："那就好，先休息一下，吃完饭再写？对了，你妈说今天晚上吃红烧肉"
```

### 5.2 场景二：客厅很乱，委婉提醒

```
触发：memory-agent VLM 分析到"客厅茶几上有很多可乐瓶和零食袋"
唤醒引擎：场景触发，低优先级，检查是否适合提醒
  - 电视没在播放 ✅
  - 不是深夜 ✅
  - 距离上次提醒 > 2 小时 ✅
  - lidicn 在客厅 ✅
对话管理器：
  上下文：lidicn，客厅很乱，晚上 21:00
  记忆：上周提醒过一次打扫，用户说"明天收拾"但没收拾
  防重复：上次说"茶几有点乱，要不要收拾一下" → 换说法
  生成回复："豪哥，茶几上的可乐瓶都快堆成山了，要不要我帮你叫个保洁？还是你自己动手？"
TTS：电视播放
```

### 5.3 场景三：久坐提醒

```
触发：人体传感器检测到 lidicn 在电竞沙发上连续 2 小时
唤醒引擎：定时检查，触发健康提醒
  - 电视在播放 → 等待暂停（不打扰）
  - 用户暂停视频 → 立即提醒
对话管理器：
  上下文：lidicn，久坐 2 小时，电竞沙发
  记忆：用户有颈椎问题（之前提过）
  生成回复："豪哥，你都坐了 2 小时了，起来活动活动吧，颈椎还要不要了？去倒杯水喝"
TTS：电视播放
```

### 5.4 场景四：早上播报

```
触发：定时唤醒，早上 8:00
唤醒引擎：检查是否适合播报
  - 客厅有人 ✅
  - 不是免打扰时段 ✅
对话管理器：
  上下文：早上 8:00，lidicn 在客厅
  记忆：读取今天的日程、天气
  生成回复："豪哥早上好，今天深圳 28 度，多云，适合出门。你今天上午 10 点有个会，别忘了。早餐吃了没？"
TTS：电视播放
```

## 8. 风险与应对

| 风险 | 影响 | 应对 |
|------|------|------|
| LLM 回复质量不稳定 | 对话不自然 | 优化 system prompt，增加场景模板，人工审核关键回复 |
| TTS 延迟高 | 对话不流畅 | 预生成常见回复音频，流式 TTS，本地缓存 |
| 主动对话打扰用户 | 用户反感 | 严格的冷却机制、免打扰时段、场景判断、用户可调节频率 |
| 记忆系统误判 | 重复或遗忘 | 多层记忆（短期/中期/长期），定期整理，用户可编辑 |
| 隐私安全 | 敏感信息泄露 | 本地存储，不上云，用户可清除记忆，敏感话题不记录 |
| TV 端播放失败 | 听不到声音 | 降级到小爱音箱，再降级到手机推送 |
