# DB 自更新通道打通 · 联调记录（2026-11-04）

> 目的：把 doubao-butler 的「E盘写码 → push GitHub → WebUI 点升级 → NAS 同步」链路跑通并留证。

## 本次做了什么

1. E 仓 `main` 推到 GitHub（SSH）：GitHub `main` 从 `36f8558` → `52a2d6c`（含修三条 DB-001/002/003 + 关闭 speak 每日预算限额）。
2. NAS 部署树 `/vol1/1000/docker/doubao-butler` 从 orphan 快照重挂到真实历史（`HEAD=52a2d6c`，dirty=0，可对 GitHub 快进）。
3. 装 DB 宿主 cron：`host_check_update.sh`（每 5 分钟）、`host_update.sh`（每分钟）。
4. `.env` 设 `SELF_UPDATE_ENABLED=true`、`UPDATE_REPO_URL=git@github.com:lidicn/doubao-butler.git`、`UPDATE_BRANCH=main`；`docker compose up -d --no-build --force-recreate` 重建后容器 healthy。
5. 手动跑检查腿生成预览件，再走一次真实升级（本文件即那次升级要落的那枚提交）。

## 以后怎么用

- 在 E 盘改码、`git commit`、推 GitHub `main`（SSH）。
- WebUI「设置 → 自更新」点「检查更新」（宿主每 5 分钟出预览）→ 「填当前版本号 → 请求更新」→ 宿主 `host_update.sh` 落码。
- 注意：日常 `main` 只落码**不重启**；要让新代码生效，发 `v<主>.<次>` 版本 tag（自动重启）或手动 `docker restart doubao-butler`。

## 2026-11-04 追加：去掉版本确认 + 开发者 agent MCP 通道

- **去掉版本号二次确认**：`POST /api/system/update` 只需 `{"ref":"main"}`（不再要 `confirm_version`）；WebUI 面板也删掉了「填入当前版本号以确认」输入框。
- **开发者 agent 升级通道（无需点 WebUI）**：在管家 MCP server 上新增三个工具，开发者 agent 用带 `BUTLER_SERVICE_TOKENS` 具名令牌的 `Authorization: Bearer <token>` 调 `POST /api/mcp`：
  - `system_update`（参数 `ref` 可省）→ 写升级请求标记，宿主 cron 1 分钟内落码；
  - `system_update_check` → 读预览（落后/脏/可快进/拒绝原因）；
  - `system_update_status` → 读执行状态（queued/applied/applied_pending_restart/failed）。
  与 AF 的「开发者 MCP」同构；WebUI 只是同一套后端的一个入口。
