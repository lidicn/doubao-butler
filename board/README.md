# 豆包管家生态 Board — PM 手册

> PM：豆包管家（兼任 DEV）| 生效：2026-09-08
> 本目录是豆包管家生态的项目管理中枢，监控所有子项目进度，协调联调，规范交接。

---

## 一、组织架构

```
                    ┌─────────────────────┐
                    │   用户（产品负责人）  │
                    └──────────┬──────────┘
                               │ 决策/需求/验收
                    ┌──────────▼──────────┐
                    │  豆包管家 PM（兼任DEV）│
                    │  监控/协调/交接/编码  │
                    └──────────┬──────────┘
                               │
          ┌────────────────────┼────────────────────┐
          │                    │                    │
   ┌──────▼──────┐     ┌──────▼──────┐     ┌──────▼──────┐
   │  TVPilot    │     │  DeskPilot  │     │  豆包管家    │
   │  电视控制    │     │  电脑控制    │     │  Agent 中枢  │
   │  (子项目)   │     │  (子项目)   │     │  (本项目)    │
   └─────────────┘     └─────────────┘     └─────────────┘
```

### 角色职责

| 角色 | 承担方 | 职责 |
|------|--------|------|
| **产品负责人** | 用户 | 需求决策、优先级、验收、资源分配 |
| **PM（兼任 DEV）** | 豆包管家 | 项目监控、进度协调、交接单管理、联调组织、豆包管家代码开发 |
| **子项目开发者** | TVPilot / DeskPilot 各自的开发 agent | 按路线图和开发计划执行、维护文档、回复交接单、输出交付报告 |

### PM 工作模式

- **兼任 DEV**：当前阶段（3 子项目、2-3 开发者），PM 同时负责豆包管家代码开发
- **编码时间**：上午（无干扰时段）
- **协调时间**：下午（状态同步/交接单/联调）
- **专职 PM 触发条件**：子项目 >5 或开发者 >4 人时，拆分专职 PM

## 四、交接单规范

### 4.1 交接单类型

| 类型 | 用途 | 示例 |
|------|------|------|
| **需求交接单** | 豆包管家需要子项目提供什么能力 | "DP 需要实现 desktop_screenshot 工具" |
| **变更交接单** | 路线变更/接口变更/决策变更 | "SSH 降级为 P2，5 道约束后才重新启用" |
| **问题交接单** | 阻塞/bug/风险 | "mytv HTTP API 10481 不可达，换台场景阻塞" |
| **联调交接单** | 联调计划/验收标准/时间窗口 | "DP M5 原子工具联调，4 场景验收" |

### 4.2 交接单编号

`YYYYMMDD_NNN_项目_主题`

- YYYYMMDD：发出日期
- NNN：当日序号（001 起）
- 项目：接收方项目名（tvpilot/deskpilot/doubao-butler）
- 主题：简短描述

示例：`20260908_001_deskpilot_M5原子工具联调.md`

### 4.3 交接单状态机

```
待回复 ──→ 进行中 ──→ 已完成
   │          │
   │          └──→ 已拒绝（需说明原因）
   │
   └──→ 已关闭（超时无进展，PM 主动关闭）
```

- 发出后标记 `待回复`
- 收到回复单后改 `进行中`
- 对方完成并验收后改 `已完成`
- 超过 2 周无进展，PM 主动关闭并说明原因

### 4.4 交接单存放位置

- **发出的交接单**：`board/handoffs/`（PM 管理）
- **同时复制一份到接收方项目的 doc/ 目录**（确保接收方看得到）
- **收到的回复单**：`board/replies/`（PM 管理）

### 4.5 交接单必含字段

见 `templates/handoff_template.md`，核心字段：
- 编号/类型/优先级/发起方/接收方
- 背景/原因
- 具体需求（可执行、可验收）
- 验收标准
- 建议截止时间
- 状态/回复单链接

## 五、回复单规范

### 5.1 回复单要求

接收方收到交接单后，**必须在 24 小时内回复**（P0 交接单 4 小时内）。

回复单必含字段（见 `templates/reply_template.md`）：
- 对应交接单编号
- 回复方/回复时间
- 结论（接受/部分接受/拒绝+原因）
- 具体计划/排期
- 预计完成时间
- 实际完成时间（完成后更新）
- 验收结果（完成后更新）

### 5.2 回复单存放位置

- 接收方项目的 doc/ 目录（命名：`回执_XXX.md` 或 `reply_XXX.md`）
- 同时复制一份到 `board/replies/`

## 六、联调管理

### 6.1 联调触发条件

子项目完成新工具/新版本后，发联调交接单给豆包管家，包含：
- 工具清单（名称/参数/返回示例/错误码）
- 部署信息（NAS 地址/端口/Token）
- 建议联调窗口
- 自测结果（全量测试通过 + 冒烟测试）

### 6.2 联调流程

1. 子项目发联调交接单 → PM 评估优先级和排期
2. 豆包管家接入工具（Client + tools.py 注册 + 观察验证器）
3. 部署 NAS → 冒烟测试
4. 联调验收场景（≥3 个）
5. 输出联调验收报告
6. 问题 → 交接单跟踪 → 修复 → 回归

### 6.3 联调验收标准

见 `开发规范_v1.0.md` §六。

## 七、风险管理

### 7.1 风险识别

PM 每 2 天状态同步时识别以下风险：
- 进度偏差（里程碑延期 >3 天）
- 阻塞（依赖未就绪/技术难题）
- 质量风险（测试失败/规范违规）
- 安全风险（危险操作无确认闸/审计缺失）
- 资源风险（开发者精力不足/环境问题）

### 7.2 风险应对

| 风险等级 | 应对 |
|---------|------|
| **P0（阻塞主线）** | 立即发问题交接单，PM 介入协调，每日跟进 |
| **P1（影响里程碑）** | 发问题交接单，2 天内跟进，调整排期 |
| **P2（潜在风险）** | 记录在 status.md，每周回顾 |

### 7.3 当前已知风险

见 `status.md` 风险段。

## 八、决策机制

### 8.1 决策层级

| 决策类型 | 决策方 | 示例 |
|---------|--------|------|
| **产品决策** | 用户 | 优先级/需求范围/验收标准/资源分配 |
| **技术决策** | PM（兼任 DEV） | 架构选型/技术方案/规范制定/接口设计 |
| **执行决策** | 子项目开发者 | 具体实现方式/代码结构/测试用例 |

### 8.2 需用户决策的事项

PM 遇到以下情况必须向用户请示：
- 需求范围变更（新增/删减功能）
- 优先级调整（P0/P1/P2 变更）
- 资源分配（开发者精力/时间/环境）
- 重大技术路线变更（框架选型/架构重构）
- 安全策略变更（SSH 权限/确认闸/审计）
- 验收标准变更

### 8.3 决策记录

所有重要决策必须记录：
- 路线图/开发计划中的决策说明
- 变更交接单（路线/接口/决策变更）
- status.md 中的决策记录段
