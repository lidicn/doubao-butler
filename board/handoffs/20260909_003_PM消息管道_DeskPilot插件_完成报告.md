## 二、API 文档

### 2.1 发送消息

```
POST /api/v1/pm/send
Authorization: Bearer <deskpilot-token>
Content-Type: application/json

{
  "target": "PM" | "TP" | "DP",   // 必填，目标对话
  "message": "消息内容",            // 必填，UTF-8，≤4096 字符
  "press_enter": true              // 可选，默认 true；false 仅粘贴不发送
}
```

成功（200）：
```json
{ "ok": true, "target": "TP", "message_length": 128, "timestamp": "2026-09-09T12:00:00" }
```

失败（按错误码映射 HTTP 状态）：
```json
{ "ok": false, "error": "screen_locked", "message": "屏幕已锁定，无法操作豆包，请解锁后重试" }
```

| 错误码 | HTTP | 含义 |
|--------|------|------|
| `invalid_parameter` | 400 | target 非 PM/TP/DP 或 message 为空 |
| `screen_locked` | 409 | 屏幕锁定（LogonUI 运行中） |
| `window_not_found` | 404 | 未找到豆包窗口 |
| `internal_error` | 500 | 插件未启用/非 Windows/执行异常 |
| `unavailable` | 503 | 桌面代理未运行（用户未登录） |

### 2.2 健康检查

```
GET /api/v1/pm/health
Authorization: Bearer <deskpilot-token>
```

```json
{
  "ok": true,
  "enabled": true,
  "doubao_window_found": true,
  "last_send_time": "2026-09-09T11:55:00",
  "total_sent": 42,
  "total_failed": 3
}
```

## 三、配置说明（`config/deskpilot.yaml`）

```yaml
pm_messenger:
  enabled: true                  # 总开关（false 时 /send 拒绝执行）
  doubao_window_keyword: "豆包"   # 窗口标题关键词
  hotkeys:                       # 目标对话快捷键（^=Ctrl）
    PM: "^1"
    TP: "^2"
    DP: "^3"
  send_delay_ms: 500             # 回车发送后等待毫秒
  audit_retention_days: 30       # 审计日志保留天数
```

- 支持环境变量覆盖：`DESKPILOT_PM_MESSENGER__ENABLED=false` 等。
- 配置热重载：修改 yaml 后自动生效（config.py 惰性热重载），无需重启。

## 四、架构说明（双进程）

```
豆包管家 PM ──POST──> DeskPilot Gateway (Session 0, :8765) /api/v1/pm/send
                              │ desktop_bridge（auto/proxy 自动选择）
                              ▼
                    desktop_agent (Session 1, :18765) /exec
                              │ pm_messenger_control.send()
                              ▼
              激活豆包窗口 → Ctrl+N 切目标对话 → ctypes 剪贴板 UTF-16
              → Ctrl+V 粘贴 → 回车发送（press_enter=true）
```

- **消息发送器只运行在 desktop_agent（用户登录会话 Session 1）**，Session 0 服务进程不直接操作桌面（与 M6.5 双进程架构一致）。
- 剪贴板用 **ctypes（GlobalAlloc/GlobalLock/SetClipboardData，CF_UNICODETEXT UTF-16）**，非 PowerShell Set-Clipboard（中文不乱码）。
- 统计（total_sent/failed/last_send_time）存 desktop_agent 进程内，/health 经代理读取。

## 七、关键踩坑记录

1. **ctypes 64 位指针截断**：`GlobalAlloc`/`GlobalLock` 未声明 restype 时默认按 32 位 `c_int` 截断 HGLOBAL → `GlobalLock failed`。已用 `_fix_ctypes_signatures()` 显式声明 `c_void_p` restype/argtypes 修复。
2. **审计完整性**：发送的提前返回路径（锁屏/找窗/禁用/未知目标/非 Windows）也要计入统计与审计（`_fail()` 统一出口），保证「每次发送」都有记录。
3. **测试客户端编码**：Windows PowerShell 5.1 `Invoke-RestMethod` 发送 body 会以 ANSI 编码导致中文乱码（`?`），**这是客户端问题非服务端**；真实 PM 客户端（Python httpx/requests UTF-8）发送中文完整无乱码。
