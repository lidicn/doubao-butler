## 一、背景与原因

豆包管家正在构建"统一指令中心 + 执行管道"架构：
- TP/DP（豆包对话）不再直接操作电脑，而是通过 DeskPilot API 执行所有操作
- DeskPilot 作为执行管道，记录所有操作日志，管家可查询监控
- 解决当前架构的核心痛点：TP/DP 状态只有"开始/完成"，没有中间态、无法终止、无法检测错误

当前 DeskPilot 已有桌面控制 API（screenshot/click/type 等），但缺少：
1. 命令执行 API（TP/DP 需要执行 shell 命令）
2. 操作日志（所有 API 调用的记录，供管家查询）
3. 日志查询 API（管家按 session_id 查询某任务的操作记录）
4. 危险命令黑名单（防止 TP/DP 误操作，补充豆包风控）
5. 超时和资源控制（防止命令卡死或占满系统资源）

## 二、具体需求

### 2.1 命令执行 API

**端点**：`POST /api/v1/exec`

**请求参数**：
```json
{
  "command": "python test.py",       // 要执行的命令（必填）
  "session_id": "TASK-20260908-005", // 任务 ID（必填，用于日志隔离）
  "operator": "TP",                   // 调用者（TP/DP/PM，必填）
  "timeout": 60,                      // 超时秒数（可选，默认 60，最大 300）
  "cwd": "E:\\NAS\\TVPilot",         // 工作目录（可选，默认 DeskPilot 启动目录）
  "env": {"KEY": "value"}             // 环境变量（可选）
}
```

**响应（成功）**：
```json
{
  "ok": true,
  "tool": "exec",
  "result": {
    "exit_code": 0,
    "stdout_tail": "测试通过\n",      // stdout 最后 4096 字符
    "stderr_tail": "",                 // stderr 最后 4096 字符
    "duration_ms": 1200,
    "timed_out": false
  }
}
```

**响应（失败/超时）**：
```json
{
  "ok": false,
  "tool": "exec",
  "error": "timeout | dangerous_command | internal_error",
  "message": "命令执行超时（60秒），已终止"
}
```

**行为要求**：
- 同步执行，等待命令完成或超时后返回
- 超时后自动杀掉进程（包括子进程）
- stdout/stderr 只保留最后 4096 字符（防止大输出撑爆响应）
- 完整输出存到本地文件（如 `logs/exec/{session_id}_{timestamp}.log`），响应里可返回文件路径
- 执行前检查危险命令黑名单（见 2.4），命中则拒绝执行

### 2.2 操作日志

**记录范围**：所有 API 调用（包括现有桌面控制 API 和新增的 exec/file API）

**日志字段**：
```json
{
  "id": 1,
  "timestamp": "2026-09-08T20:30:00.123Z",
  "session_id": "TASK-20260908-005",
  "operator": "TP",
  "api_endpoint": "/api/v1/exec",
  "action": "exec",
  "params": {"command": "python test.py", "cwd": "E:\\NAS\\TVPilot"},
  "success": true,
  "exit_code": 0,
  "duration_ms": 1200,
  "result_tail": "测试通过",
  "error": null
}
```

**存储**：本地 SQLite（`data/operation_logs.db`），表名 `operation_logs`

**索引**：`session_id`、`operator`、`timestamp`（方便查询）

**脱敏**：自动脱敏 params 和 result_tail 中的敏感信息（密码、密钥、token 等），可简单匹配常见关键词（password/secret/token/key）并替换为 `***`

### 2.3 日志查询 API

**端点**：`GET /api/v1/logs`

**查询参数**：
- `session_id`（可选）：按任务 ID 过滤
- `operator`（可选）：按调用者过滤（TP/DP/PM）
- `limit`（可选）：返回条数，默认 50，最大 500
- `offset`（可选）：分页偏移
- `since`（可选）：只返回该时间戳之后的日志（ISO 格式）

**响应**：
```json
{
  "ok": true,
  "data": {
    "total": 123,
    "items": [
      { /* 日志字段，见 2.2 */ }
    ]
  }
}
```

### 2.4 危险命令黑名单

**硬拒绝（直接返回错误，不执行）**：
- `rm -rf /`、`rm -rf /*`、`rm -rf C:\`、`rm -rf D:\` 等根目录删除
- `format`、`mkfs`、`diskpart` 等磁盘格式化
- `dd if=/dev/zero`、`dd if=/dev/random` 等磁盘写入
- `shutdown`、`reboot`、`halt`、`poweroff` 等系统关机重启
- `taskkill /F /IM explorer.exe`、杀死系统关键进程
- 修改注册表启动项、系统服务配置等

**需警告（执行但记录 high_risk 标记）**：
- `rm -rf`（非根目录）
- `kill`、`taskkill`（非系统进程）
- 修改系统配置文件（hosts、环境变量等）
- 安装/卸载软件

**实现方式**：
- 命令执行前，对 command 做正则匹配（不区分大小写）
- 命中硬拒绝列表 → 返回 `dangerous_command` 错误，不执行
- 命中警告列表 → 执行，但在操作日志里标记 `high_risk: true`
- 黑名单列表存配置文件（`config/dangerous_commands.yaml`），可维护

### 2.5 超时和资源控制

- **默认超时**：60 秒（可通过 API 参数覆盖，最大 300 秒）
- **超时处理**：杀掉进程树（包括子进程），返回 `timeout` 错误
- **并发控制**：最多同时执行 3 个命令（可配置），超出则排队或返回 `too_many_concurrent` 错误
- **资源限制**：可选，用 `psutil` 限制 CPU/内存（如果实现成本高，先不做，记录到 backlog）

### 2.6 文件操作 API（可选，如时间允许）

如果时间允许，增加以下 API（TP/DP 写代码需要）：
- `POST /api/v1/file/write`：写文件（参数：path、content、session_id、operator）
- `GET /api/v1/file/read`：读文件（参数：path，返回 content）
- `GET /api/v1/file/list`：列目录（参数：path，返回文件列表）

如果时间不够，先不做，TP/DP 可以通过 exec API 用 `echo`/`type` 等命令操作文件（但不推荐，后期补）。

## 三、验收标准

- [ ] `POST /api/v1/exec` 可正常执行命令，返回 exit_code、stdout_tail、duration_ms
- [ ] 命令超时（如 `sleep 100`，timeout=5）能自动杀掉进程并返回 timeout 错误
- [ ] 危险命令（如 `rm -rf /`）被拒绝，返回 dangerous_command 错误，不执行
- [ ] 所有 API 调用（exec + 现有桌面控制 API）都记录到 operation_logs 表
- [ ] `GET /api/v1/logs?session_id=xxx` 能查询某任务的操作日志，按时间排序
- [ ] 操作日志中敏感信息（password/secret/token）被脱敏为 `***`
- [ ] 并发执行 4 个命令时，第 4 个排队或返回 too_many_concurrent（不崩溃）
- [ ] 大输出命令（如 `dir /s C:\`）的 stdout_tail 不超过 4096 字符
- [ ] 全量测试通过（现有 595+ 测试不破坏）
- [ ] 交付文档：API 文档、危险命令黑名单说明、操作日志字段说明
