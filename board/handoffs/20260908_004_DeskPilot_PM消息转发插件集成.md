## 一、背景与原因

豆包管家（PM）需要一个通道，让用户从手机 PWA 发的消息能直接出现在电脑上的豆包 PM 对话里。

当前已通过独立脚本 `C:\tools\pm_forwarder.py`（监听 18766 端口）+ `C:\tools\pm_send_to_pm.py` 实现了该功能，端到端验证通过。但独立脚本存在以下问题：

1. **运维成本高**：需要单独启动、单独维护、单独配置开机自启
2. **与 DeskPilot 定位重叠**：DeskPilot 本身就是桌面控制中枢，消息转发本质上是桌面操控的一种
3. **双进程架构已就绪**：DeskPilot v2.6 已实现管理员服务 + 用户态 desktop_agent 双进程方案，desktop_agent 在用户会话里运行，天然具备桌面操控权限

因此，将 PM 消息转发功能集成到 DeskPilot 作为插件，废弃独立的 pm_forwarder.py。

## 二、具体需求

### 2.1 插件形式

- 在 DeskPilot 中新增一个插件模块，命名建议：`pm_forward` 或 `pm_notify`
- 插件注册一个新的 API 端点：`POST /api/v1/pm-forward/send`（路径可调整，但需告知管家侧）
- 鉴权沿用 DeskPilot 现有全局 Bearer token 机制

### 2.2 API 请求/响应格式

**请求**：
```json
{
  "text": "要发送的消息内容（支持中文，最长 4096 字符）"
}
```

**响应（成功）**：
```json
{
  "ok": true,
  "tool": "pm_forward_send",
  "result": { "message": "发送完成" },
  "cost_ms": 7200
}
```

**响应（失败）**：
```json
{
  "ok": false,
  "tool": "pm_forward_send",
  "error": "screen_locked | window_not_found | internal_error",
  "message": "具体错误描述"
}
```

### 2.3 执行逻辑（核心）

插件收到请求后，**必须在用户会话里执行**以下操作（不能在 Session 0 服务进程里执行）：

1. **锁屏检测**：检查 `LogonUI.exe` 进程是否存在，存在则返回 `screen_locked` 错误
2. **查找豆包窗口**：EnumWindows 遍历可见窗口，找到标题含"豆包"的窗口
   - 优先找标题含"PM"的（如"PM - 豆包"）
   - 其次找任何含"豆包"的（因为豆包软件只有一个窗口，标题随当前对话变化，如"TP - 豆包"）
3. **激活窗口**：AttachThreadInput + SetForegroundWindow 激活豆包窗口
4. **切换到 PM 对话**：模拟 Ctrl+1（豆包软件快捷键，第一个对话=PM）
5. **输入消息**：通过剪贴板（`clip.exe` 或 SetClipboardData）+ Ctrl+V 粘贴（不用 SendInput，兼容性问题；不用 pyautogui，fail-safe 问题）
6. **发送**：模拟回车键
7. **返回结果**：同步等待执行完成，返回成功/失败 + 错误信息

### 2.4 执行方式（二选一，推荐方案 A）

**方案 A（推荐）：通过 desktop_agent 执行**
- 在 desktop_agent（`backend/desktop_agent.py`）的 `/exec` 分发中新增一个动作类型，如 `pm_forward`
- 插件 API 收到请求后，通过 desktop_bridge 转发到 desktop_agent 执行
- desktop_agent 在用户会话里直接用 ctypes 执行上述逻辑
- 优点：复用双进程架构，权限正确，与现有桌面操控一致

**方案 B（备选）：插件内 subprocess 执行脚本**
- 插件 API 收到请求后，用 `subprocess.run` 同步执行 `pm_send_to_pm.py`（需将脚本纳入 DeskPilot 项目，如 `scripts/pm_send_to_pm.py`）
- 前提：DeskPilot 服务进程必须在用户会话里运行（不能是 Windows Service）
- 优点：实现简单，复用已验证的脚本
- 缺点：依赖外部脚本，不如方案 A 优雅

### 2.5 废弃独立脚本

- 插件上线并验证通过后，告知管家侧切换 API 地址
- 管家侧停止使用 `http://192.168.2.201:18766/send`，改用 DeskPilot 的新 API

## 五、参考资料

### 5.1 已验证的核心脚本（pm_send_to_pm.py）

```python
r"""TP/DP→PM 消息发送脚本（豆包 Ctrl+1 对话）
用法: python pm_send_to_pm.py <base64编码的消息内容>
纯键盘操作：激活豆包→Ctrl+1→剪贴板输入→回车
"""
import sys
import base64
import ctypes
import ctypes.wintypes
import time
import subprocess

user32 = ctypes.windll.user32

def is_screen_locked():
    try:
        r = subprocess.run(["tasklist", "/FI", "IMAGENAME eq LogonUI.exe"],
                          capture_output=True, text=True, timeout=5)
        return "LogonUI.exe" in r.stdout
    except Exception:
        return False

def find_doubao_pm():
    """找到豆包窗口（标题含'豆包'即可，不要求含'PM'，因为标题随当前对话变化）。
    优先找标题含'PM'的，其次找任何含'豆包'的。"""
    all_doubao = []
    pm_doubao = []
    def cb(hwnd, lp):
        l = user32.GetWindowTextLengthW(hwnd)
        if l > 0:
            b = ctypes.create_unicode_buffer(l + 1)
            user32.GetWindowTextW(hwnd, b, l + 1)
            title = b.value
            if "豆包" in title:
                all_doubao.append(hwnd)
                if "PM" in title:
                    pm_doubao.append(hwnd)
        return True
    WNDPROC = ctypes.WINFUNCTYPE(ctypes.wintypes.BOOL, ctypes.wintypes.HWND, ctypes.wintypes.LPARAM)
    user32.EnumWindows(WNDPROC(cb), 0)
    if pm_doubao:
        return pm_doubao[0]
    if all_doubao:
        return all_doubao[0]
    return None

def force_foreground(hwnd):
    fg = user32.GetForegroundWindow()
    fg_thread = user32.GetWindowThreadProcessId(fg, None)
    cur_thread = ctypes.windll.kernel32.GetCurrentThreadId()
    if fg_thread != cur_thread:
        user32.AttachThreadInput(cur_thread, fg_thread, True)
    user32.SetForegroundWindow(hwnd)
    time.sleep(0.8)
    if fg_thread != cur_thread:
        user32.AttachThreadInput(cur_thread, fg_thread, False)

def hotkey(*vks):
    for v in vks:
        user32.keybd_event(v, 0, 0, 0)
        time.sleep(0.03)
    time.sleep(0.05)
    for v in reversed(vks):
        user32.keybd_event(v, 0, 0x0002, 0)
    time.sleep(0.5)

def type_text(text):
    p = subprocess.Popen(['clip'], stdin=subprocess.PIPE)
    p.communicate(text.encode('utf-8'))
    time.sleep(0.3)
    hotkey(0x11, 0x56)  # Ctrl+V
    time.sleep(0.5)
```

### 5.2 已踩过的坑（务必避免）

| 方案 | 失败原因 |
|------|----------|
| DeskPilot system_run（CREATE_NO_WINDOW + 异步） | 子进程窗口站权限不足，EnumWindows 找不到窗口；异步不返回结果 |
| 独立转发服务（进程内 SendInput Unicode） | SendInput 在豆包里输入不生效（焦点问题） |
| 独立转发服务（进程内剪贴板 GlobalAlloc/GlobalLock） | GlobalLock 返回空指针，ctypes.memmove 访问违规崩溃 |
| DeskPilot desktop/key（PyAutoGUI） | 服务进程鼠标位置异常，触发 PyAutoGUI fail-safe |
| pm_send_to_pm.py（要求标题含"PM"） | 豆包窗口标题随当前对话变化，TP 对话时标题是"TP - 豆包"，找不到 |

**唯一验证成功的方式**：ctypes 直接操作桌面（EnumWindows + AttachThreadInput + keybd_event）+ 剪贴板（clip.exe + Ctrl+V），在用户会话里同步执行。
