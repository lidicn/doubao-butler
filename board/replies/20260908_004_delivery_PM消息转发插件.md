## 二、插件说明

### 2.1 架构

```
豆包管家 PWA / 任务完成通知
   │ POST /api/v1/pm-forward/send  {"text": "..."}
   ▼
管理员服务（Session 0） backend/api/v1/pm_forward.py
   │ desktop_bridge.pm_forward_send(text)  （auto/proxy 模式）
   ▼
desktop_agent（用户态 Session 1）POST /exec {"tool": "pm_forward_send", ...}
   │ pm_forward_control.send_to_pm(text)（ctypes 直接操作桌面）
   ▼
激活豆包窗口 → Ctrl+1 切 PM 对话 → clip.exe 剪贴板 + Ctrl+V → 回车发送
```

关键点：**桌面操作只在用户态代理执行**（Session 0 服务进程不碰桌面，符合双进程方案与
踩坑记录——服务进程 EnumWindows 找不到窗口 / SendInput 不生效）。

## 三、API 文档

### `POST /api/v1/pm-forward/send`

鉴权：`Authorization: Bearer <token>`（与 DeskPilot 全局一致）

**请求体**：
```json
{ "text": "要发送的消息内容（支持中文，1–4096 字符）" }
```

**成功响应（200）**：
```json
{
  "ok": true,
  "tool": "pm_forward_send",
  "result": { "message": "发送完成" },
  "cost_ms": 7200,
  "error": null
}
```

**失败响应（错误码矩阵）**：

| 错误码 | HTTP | 触发条件 | 建议 |
|--------|------|----------|------|
| `screen_locked` | 409 | LogonUI.exe 存在（屏幕锁定） | 解锁后重试 |
| `window_not_found` | 404 | 未找到标题含「豆包」的窗口 | 启动豆包后重试 |
| `internal_error` | 500 | 执行过程中内部异常 | 重试 1 次后上报 |
| `unavailable` | 503 | 桌面代理未运行 / 鉴权失败 / 转发失败 | 确认用户已登录后重试 |

### 时序（同步，约 7 秒）

1. 锁屏检测（tasklist 查 LogonUI.exe）→ 锁定即 `screen_locked`，不执行操作
2. EnumWindows 找豆包窗口（优先标题含「PM」，其次任意含「豆包」→ 兼容 TP 对话场景）
3. AttachThreadInput + SetForegroundWindow 激活窗口
4. Ctrl+1 切到 PM 对话（保险起见，即使当前已是 PM）
5. `clip.exe` 写入剪贴板 + Ctrl+V 粘贴（支持中文）
6. 回车发送，等待 2s，返回结果
